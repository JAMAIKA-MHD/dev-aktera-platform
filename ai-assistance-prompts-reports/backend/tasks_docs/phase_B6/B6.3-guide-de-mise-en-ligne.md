## 1. Objectif

Écrire le guide pour mettre en ligne dans le bon ordre, sans casser la production. Pour chaque étape : la commande exacte, ce qu'il faut vérifier, et comment revenir en arrière. **Je rédige ; tu lances les commandes cloud** (rules §6.6). Aucune commande cloud n'a été lancée par moi.

**Livrable :** [`../../deploiement.md`](../../deploiement.md).

## 3. Décisions et écarts

| Décision                                                                 | Alternative écartée                                 | Raison                                                                                                                                                                                                                    |
| ------------------------------------------------------------------------ | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **`stable` déployé avant `select-prize`** (étapes 6 puis 7)              | L'ordre de `tasks.md` (`stable` en dernier)         | Avec l'ordre de `tasks.md`, `stable` servirait l'ancienne page, sans consentement, face à la nouvelle `select-prize`, qui la refuse. Interdit par `rules.md` §3.3, qui l'emporte sur `tasks.md`. **Écart signalé**        |
| Migration B6.2 déplacée hors de `supabase/migrations/` pendant l'étape 3 | `supabase migration repair`, ou SQL collé à la main | `db push` pousse tout ce qui manque, sans version cible. Déplacer le fichier le temps du push est simple, visible (`git status`), et `--dry-run` le vérifie                                                               |
| Correction du coupon (`20260929150000`) poussée à l'étape 3              | Avec B6.2 à l'étape 9                               | L'ancienne `select-prize` n'appelle pas `claim_campaign_prize_coupon` (vérifié dans `97c8022`) : aucun risque, et la nouvelle en a besoin dès l'étape 7                                                                   |
| `.env.production.local` pour le build                                    | Construire avec `.env.local`                        | Vite lit `.env.local` même pour `npm run build` : le `dist/` actuel contient `127.0.0.1:54321` (vérifié). Le fichier propre à la production l'emporte ; il est ignoré par git (`.env*`). Le guide fait vérifier le bundle |
| Code de `select-prize` en ligne copié depuis le tableau de bord          | `supabase functions download`                       | Cette commande écraserait `supabase/functions/select-prize/index.ts` du dépôt                                                                                                                                             |
| Test du consentement sur un identifiant de campagne inexistant           | Une vraie partie                                    | `select-prize` vérifie le consentement **avant** de lire la base (étape 2 de son en-tête) : aucune écriture                                                                                                               |

**Hypothèse notée dans le guide :** `demo` et `stable` partagent le même projet Supabase (un seul projet Firebase `octoreach-mvp`, une seule configuration). Sinon, les étapes base et fonction se répètent par projet.

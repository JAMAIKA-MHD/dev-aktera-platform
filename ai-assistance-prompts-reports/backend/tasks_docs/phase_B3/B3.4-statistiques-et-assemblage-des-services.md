## 5. Le code expliqué

### 5.1 `createSupabaseAnalyticsTracker({ client })`

- `experience_viewed` → `record_campaign_impression` : une visite, temps 0.
- `form_submitted` → la même fonction, avec « formulaire rempli » et le **temps passé** depuis la visite de la même session.
- **Tous les autres événements sont ignorés** (ils sont affichés dans la console en développement). `select-prize` enregistre déjà « partie jouée » de son côté.
- **Sans campagne** (aperçu autonome) : rien n'est envoyé.
- **Fire-and-forget :**
  - l'appel n'est jamais attendu ;
  - une erreur est avalée ;
  - l'appel part dans une promesse, donc même une exception immédiate du client ne remonte pas ;
  - aucune donnée personnelle n'est envoyée (session, campagne, navigateur seulement).
- La fonction SQL fusionne les appels d'une même session (une ligne par campagne et par session). L'ancien « battement de cœur » toutes les 5 s de l'ancienne page n'est pas repris (tasks.md §0.4).

### 5.2 `createStudioServices({ client, supabaseUrl, organizationId, campaignId, rules, repository? })`

- **Sauvegarde :** le dépôt Supabase (B3.1), ou celui qu'on lui donne (B4.3 l'enveloppera pour importer les designs du navigateur).
- **Tirage :** **démo** (`createDemoParticipationGateway`), avec les règles de la campagne. Un aperçu ne consomme **jamais** de vrai stock (décision D3).
- **Images :** Supabase Storage (B3.3).
- **Statistiques :** console. **Vérification humaine :** aucune.

### 5.3 `createPublicServices({ client, supabaseUrl, availability })`

- **Tirage : `live`** (`select-prize`, B3.2). C'est le seul mode accepté par la page publique.
- **Sauvegarde : lecture seule.** `load` renvoie `null`, car le design arrive avec la campagne ; `save` refuse.
- **Images :** résolution seulement, par `createDataUrlAssetStorage` avec `resolveStorage` = URL publique. Un joueur n'envoie jamais d'image. Les anciens designs en data URL s'affichent toujours.
- **Statistiques :** `supabaseAnalyticsTracker`.

### 5.4 `createLocalServices({ …, resolveStorage })`

Nouvelle option facultative, transmise au stockage local. Le cadre d'aperçu `/xp-frame` s'en servira en B4.2 pour afficher les images Storage. Sans elle, le comportement est **exactement** celui d'avant.

## 6. Décisions et alternatives

| Décision                                     | Alternative écartée                                         | Raison                                                                                                          |
| -------------------------------------------- | ----------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------- |
| N'exporter que `createPublicServices`        | Exporter aussi `createStudioServices` et `publicStorageUrl` | Seule la page publique (hors module) en a besoin ; le Studio assemble ses services à l'intérieur du module (R6) |
| 2 événements envoyés                         | Tous                                                        | Le tableau de bord actuel ne lit que visites, formulaire et parties ; pas de table d'événements dans le MVP     |
| Dépôt en lecture seule pour la page publique | Le dépôt Supabase                                           | Un joueur anonyme n'a aucun droit sur `campaign_experiences` ; le design vient de `get_public_experience`       |

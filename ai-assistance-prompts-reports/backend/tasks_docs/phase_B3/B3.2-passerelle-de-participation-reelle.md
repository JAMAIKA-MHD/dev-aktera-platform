## 1. Objectif

Écrire la passerelle `live`, la seule autorité sur le résultat en production. Elle traduit une demande de participation du runtime en appel à `select-prize`, puis sa réponse en résultat que les écrans savent afficher. Elle confirme aussi les coupons par `confirm-coupon`.


## 5. Le code expliqué

### 5.1 `toSelectPrizeBody(request)` : demande du runtime → corps de `select-prize`

| `DrawRequest`                                        | Corps envoyé                                                                  |
| ---------------------------------------------------- | ----------------------------------------------------------------------------- |
| `campaignId`                                         | `campaign_id`                                                                 |
| `participant.phone` (déjà normalisé par le runtime)  | `phone_number`                                                                |
| `participant.fullName` / `email` (si remplis)        | `participant_name` / `participant_email`                                      |
| `gamePayload` : `none` / `quiz` / `boxes` / `hitIt`  | `game_payload` : `{}` / `{ answers }` / `{ selected_box_index }` / `{ hits }` |
| `context.sessionId`, `dwellTimeSeconds`, `userAgent` | `session_id`, `dwell_time_seconds`, `user_agent`                              |
| `clientRequestId`, `consent`, `context.source`       | `metadata.client_request_id`, `metadata.consent`, `metadata.source`           |
| `participant.wilaya` (si remplie)                    | `metadata.wilaya`                                                             |
| `humanToken` (s'il existe)                           | `metadata.human_token` (ni vérifié ni stocké par le serveur pour l'instant)   |

### 5.2 `toDrawResult({ status, body })` : réponse → résultat

Dans cet ordre :

1. **Pas de réponse** (`status: null` : réseau coupé, délai dépassé) → `NETWORK`.
2. **Succès** (`ok: true` et une participation avec un `id`) → `{ ok: true, entryId, outcome }` :
   - `isWinner` = un lot est présent ;
   - `prize` = `{ id, name, winMessage }` ;
   - `couponCode` = le code, ou `null`, par exemple quand plus aucun code n'est disponible.
3. **Un `code` d'erreur** (`select-prize` depuis B2.1) :

   | Code du serveur                                            | Code du joueur  | Pourquoi                                                   |
   | ---------------------------------------------------------- | --------------- | ---------------------------------------------------------- |
   | `ALREADY_PARTICIPATED`, `CAMPAIGN_CLOSED`, `INVALID_INPUT` | le même         | Même sens des deux côtés                                   |
   | `CONSENT_REQUIRED`                                         | `INVALID_INPUT` | Le joueur doit renvoyer le formulaire avec le consentement |
   | `DRAW_FAILED`, `SERVER_ERROR`                              | `NETWORK`       | Panne côté serveur : le joueur peut réessayer              |

4. **Statut 5xx sans code** → `NETWORK`.
5. **Ancien message, sans code** (`select-prize` déployé avant B2.1, tant que la nouvelle version n'est pas en ligne) :
   - « already participated » → `ALREADY_PARTICIPATED` ;
   - « Campaign not found. », « Campaign is not active. », « … campaign is closed … » → `CAMPAIGN_CLOSED` ;
   - « phone » ou « required » → `INVALID_INPUT`.
6. **Tout le reste** → `UNKNOWN`, réessayable, avec le message du serveur quand il y en a un.

Le runtime choisit ensuite le texte montré au joueur (fr / ar / en) d'après le code (`PARTICIPATION_ERROR_MESSAGES`). Le `message` ne sert qu'aux journaux.

### 5.3 `createSupabaseParticipationGateway({ client, availability, timeoutMs })`

- **`mode: "live"`** : la seule passerelle que la page publique acceptera (`allowedGatewayModes={["live"]}`).
- **`checkAvailability()`** renvoie la disponibilité lue avec la campagne (`get_public_experience`, B1.2), sans nouvel appel. B5.1 s'en servira pour afficher « campagne terminée » dès l'ouverture.
- **`draw(request)`** : `functions.invoke("select-prize", { body, timeout })`, 15 s par défaut.
- **`confirmCoupon(entryId)`** : `functions.invoke("confirm-coupon", { entry_id })` → `{ ok: true }`, sinon `NETWORK` (pas de réponse ou 5xx) ou `UNKNOWN`.
- **La fonction interne `invoke`** normalise ce que renvoie supabase-js :
  - réussite → `{ status: 200, body }` ;
  - réponse d'erreur (`FunctionsHttpError`, dont `context` est la réponse HTTP) → son statut et son JSON. C'est le même principe que `extractInvokeErrorMessage` dans l'ancienne page ;
  - corps non JSON → `body: null` ;
  - aucune réponse (`FunctionsFetchError`, exception, délai) → `status: null`.
- **Aucun repli** : si `select-prize` échoue, le joueur voit l'erreur et peut réessayer **avec le même `clientRequestId`**. Grâce à B2.1, le serveur lui renvoie alors le même résultat. Rien dans le navigateur ne tire au sort ni n'écrit de participation (règle 1 de `CLAUDE.md`).

## 6. Décisions et alternatives

| Décision                                         | Alternative écartée            | Raison                                                                                                                    |
| ------------------------------------------------ | ------------------------------ | ------------------------------------------------------------------------------------------------------------------------- |
| Reconnaître aussi les anciens messages           | Ne lire que les codes          | La nouvelle page peut être mise en ligne avant la nouvelle `select-prize` (tasks.md B6.3)                                 |
| `DRAW_FAILED` / `SERVER_ERROR` / 5xx → `NETWORK` | `UNKNOWN`                      | Les deux sont réessayables ; `NETWORK` affiche « Vérifiez votre réseau et réessayez », qui convient à une panne passagère |
| Option `timeout` de supabase-js                  | Un `AbortController` fait main | Déjà fournie par la bibliothèque (2.110) : moins de code                                                                  |
| Conversions dans un fichier pur à part           | Tout dans la passerelle        | Testables sans faux client, un cas par ligne                                                                              |

## 5. Le code expliqué

### 5.1 `readStoredExperience(data, scope, issues)`

Code **déplacé** depuis le dépôt local, pour que les deux dépôts réparent de la même façon :

1. `parseExperienceConfig` migre les anciennes versions, valide et remplace ce qui est abîmé par des valeurs par défaut ;
2. si le design porte un autre `campaignId` que celui demandé, il est rattaché à la bonne campagne, avec un message ;
3. renvoie `{ config, issues, recovered }`.

Le dépôt local l'appelle en lui passant son éventuel problème de JSON illisible, puis garde son propre avertissement (même texte qu'avant). Ses 20 tests passent **sans modification**.

### 5.2 `createSupabaseExperienceRepository({ client, warn })`

Le client Supabase est **reçu en paramètre** (rules §7.4) : l'adaptateur n'importe pas `src/lib/supabase.ts`, et se teste avec un faux client.

- **`load(scope)`**
  - Campagne `null` (Studio autonome) → `null`, sans appel au serveur.
  - Sinon : `select config from campaign_experiences where campaign_id = …`, avec les règles d'accès de B1.2 (seulement les membres de l'organisation).
  - Pas de ligne → `null` : le Studio part des valeurs par défaut.
  - Une ligne → `readStoredExperience`, avec un avertissement si elle a dû être réparée.
  - **Erreur du serveur → exception** « Could not load the saved design… ». C'est un choix voulu (rules §7.5) : renvoyer `null` ferait croire qu'il n'y a rien. Le Studio enregistrerait alors les valeurs par défaut **par-dessus le vrai design**. B4.1 rattrapera cette exception.
- **`save(config, { expectedUpdatedAt })`**
  - Appelle `save_experience_config(p_campaign_id, p_config, p_expected_updated_at)`. `expectedUpdatedAt` absent → `null` : premier enregistrement, ou écrasement volontaire.
  - Réussite → `{ ok: true, config }` avec l'`updatedAt` fixé par le serveur. Le reste du design est celui envoyé : le serveur ne change que `updatedAt` et `campaignId`, qui est déjà le bon.
  - Correspondance des réponses :

    | Réponse du serveur                                                   | Code du port          | Message affiché dans le Studio (anglais)                                                    |
    | -------------------------------------------------------------------- | --------------------- | ------------------------------------------------------------------------------------------- |
    | `CONFLICT`                                                           | `CONFLICT`            | « This design was saved meanwhile elsewhere (another tab, window or teammate). Reload it… » |
    | `TOO_LARGE`                                                          | `STORAGE_FULL`        | « This design is too large to save, usually because of embedded images… »                   |
    | `NOT_FOUND`, `INVALID`, erreur SQL, panne réseau, réponse inattendue | `STORAGE_UNAVAILABLE` | « The design could not be saved to the server. Check your connection and your access… »     |

  - Un design autonome (`campaignId: null`) n'est **jamais** envoyé.
- **`remove(scope)`** : supprime la ligne. Une erreur est journalisée, pas levée, comme dans le dépôt local.

### 5.3 Le faux client (`__tests__/fakeSupabaseClient.ts`)

- Il imite seulement ce que les adaptateurs appellent :
  - `from(table).select().eq().maybeSingle()` ;
  - `from(table).delete().eq()` (qu'on peut attendre avec `await`) ;
  - `rpc(nom, arguments)` ;
  - `functions.invoke(nom, { body, signal })` ;
  - `storage.from(bucket).upload(chemin, contenu, options)`.
- Chaque test choisit les réponses.
- Chaque appel est enregistré dans `calls`, pour vérifier **ce qui a été envoyé**.

## 6. Décisions et alternatives

| Décision                                                     | Alternative écartée                      | Raison                                                                                 |
| ------------------------------------------------------------ | ---------------------------------------- | -------------------------------------------------------------------------------------- |
| `load` lève une exception si le serveur ne répond pas        | Renvoyer `null`                          | Ne jamais écraser un vrai design avec les valeurs par défaut                           |
| Garder les 3 codes du port                                   | Ajouter `NOT_FOUND` / `NETWORK`          | Le Studio sait déjà afficher ces 3 cas (R6 : pas de nouveau type sans besoin)          |
| Reconstruire la config renvoyée (`{ ...config, updatedAt }`) | La repasser dans `parseExperienceConfig` | Le serveur ne change que 2 champs ; une réparation inutile pourrait modifier le design |
| Faux client fait main                                        | Une bibliothèque de simulation           | Aucune dépendance nouvelle (R6)                                                        |

## 7. Tests

`supabaseExperienceRepository.test.ts`, 16 tests :

- **load :**
  - mode autonome : aucun appel ;
  - aucune ligne → `null` ;
  - design intact rendu tel quel ;
  - design abîmé réparé, avec avertissement ;
  - `campaignId` corrigé ;
  - **erreur du serveur → exception**.
- **save :**
  - envoi exact des 3 paramètres, et `updatedAt` du serveur repris ;
  - `null` pour un 1ᵉʳ enregistrement ;
  - correspondance des 4 codes serveur (`CONFLICT`, `TOO_LARGE`, `NOT_FOUND`, `INVALID`) ;
  - erreur SQL, panne réseau, réponse inattendue, `updatedAt` absent → `STORAGE_UNAVAILABLE` ;
  - design autonome jamais envoyé.
- **remove :** suppression de la bonne ligne ; erreur journalisée, pas levée ; mode autonome ignoré.

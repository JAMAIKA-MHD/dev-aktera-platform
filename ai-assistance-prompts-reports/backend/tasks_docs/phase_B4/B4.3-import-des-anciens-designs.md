## 1. Objectif

Ne pas perdre les designs faits dans le Studio **avant** le branchement sur Supabase. Ils n'existent que dans le navigateur qui les a créés (`localStorage`, clé `xp:experience:v1:<campagne>`). À la première ouverture d'une campagne dans le nouveau Studio, si le serveur n'a rien et que ce navigateur a un design, **il est envoyé une fois sur le serveur**, puis servi par lui.

## 5. Le code expliqué

`createImportingExperienceRepository({ remote, local, getStorage, warn })` enveloppe deux dépôts :

- **`load(scope)`**
  1. Lit d'abord le serveur. Une erreur du serveur **remonte**, pour que le Studio affiche son message au lieu des valeurs par défaut (B4.1).
  2. Le serveur a un design → c'est lui.
  3. Sinon, si le marqueur `xp:experience:imported:<campagne>` existe → `null`, car ce design a déjà été importé, ou supprimé exprès du serveur.
  4. Sinon, lit le navigateur. Rien → `null`.
  5. Sinon, **l'envoie au serveur** (`save` sans version attendue, puisque le serveur est vide).
     - **Réussite** : marqueur posé, et le design est renvoyé **avec la version du serveur** (`updatedAt`), pour que les enregistrements suivants soient protégés contre les conflits.
     - **Échec** (trop gros, serveur indisponible) : un avertissement dans la console, et le design du navigateur est renvoyé quand même. La marque le retrouve et peut continuer ; la prochaine sauvegarde automatique, ou la prochaine ouverture, le renverra.
- **`save`** → le serveur.
- **`remove`** → le serveur, puis pose le marqueur : un design supprimé exprès ne revient jamais du navigateur.

**La copie du navigateur n'est jamais effacée** : c'est un filet de sécurité.

**Les images de ces anciens designs restent en data URL** : elles s'affichent toujours, sans conversion (tasks.md §0.4). Une nouvelle image envoyée ensuite ira dans Storage.

## 6. Décisions et alternatives

| Décision                                            | Alternative écartée                 | Raison                                                                      |
| --------------------------------------------------- | ----------------------------------- | --------------------------------------------------------------------------- |
| Import automatique et silencieux                    | Demander à la marque                | Aucun risque (le serveur est vide pour cette campagne) ; une étape de moins |
| Marqueur par campagne                               | Effacer la copie du navigateur      | Garder un filet de sécurité                                                 |
| Renvoyer le design du navigateur si l'import échoue | Renvoyer `null`                     | Ne jamais faire disparaître le travail de la marque                         |
| Pas de conversion des images                        | Les envoyer dans Storage à l'import | Moins de code (R6) ; elles s'affichent déjà                                 |

## 7. Tests

`importingExperienceRepository.test.ts`, 7 tests :

- le design du serveur l'emporte, sans lire le navigateur ;
- **import unique** : envoyé une fois, version du serveur reprise, marqueur posé, servi ensuite par le serveur, copie du navigateur conservée ;
- ni serveur ni navigateur → `null` ;
- un design supprimé du serveur ne revient jamais ;
- import en échec : on continue sur le design du navigateur, avertissement, nouvel essai à l'ouverture suivante ;
- une erreur du serveur remonte ;
- `save` va au serveur.

**À vérifier par toi, dans ton navigateur habituel** (celui où tu as fait des designs avant le branchement) :

1. `npm run dev`, puis ouvre une vraie campagne dans le Studio. Tu dois retrouver le design que tu y avais fait.
2. Dans Supabase Studio local (`http://127.0.0.1:54323`), table `campaign_experiences` : une ligne pour cette campagne.
3. Ouvre la même campagne dans un autre navigateur : même design.

⚠️ Tes anciens designs sont rangés par **identifiant de campagne**. Ils ne seront retrouvés que si les campagnes ont gardé leur identifiant, ce qui est le cas tant qu'aucun `db reset` n'a été fait (B0.1).

## 9. Non-régression

- Le Studio autonome n'est pas concerné (pas de campagne).
- Une campagne qui a déjà un design sur le serveur : comportement identique à B4.1.

## 10. Écarts, imprévus et points d'attention

- L'import est fait par **le navigateur qui ouvre la campagne en premier**. Si deux navigateurs ont chacun une ancienne version, c'est le premier qui l'emporte. L'autre copie reste dans son navigateur, sans être importée.

## 1. Objectif

Donner au design du Studio **sa propre table** sur le serveur, séparée des règles de la campagne (décision D1 du 2026-09-29). Donner aussi aux joueurs **une seule porte d'entrée publique**, qui ne renvoie que ce qu'ils ont le droit de voir.

Les tâches B3.1 (le Studio enregistre ici) et B5.2 (la page `/play/:slug` lit ici) s'appuient sur cette tâche.

## 2. Avant / après

- **Avant :** le design n'existait que dans le navigateur (`localStorage`). Pour lire une campagne, un joueur aurait dû avoir un accès direct aux tables `campaigns`, `prizes` et `quiz_questions`, bonnes réponses comprises.
- **Après :**

```
Studio (membre connecté) ── save_experience_config ──► campaign_experiences (1 ligne / campagne)
                         ── select (RLS : son organisation)  ◄──┘
Joueur (anonyme) ── get_public_experience(slug) ──► { campaign, prizes, quiz, availability, experience }
                                                     (champs sûrs uniquement)
```

La table `campaigns` **n'est pas modifiée**. Le Wizard, qui réécrit `player_screen_config` à chaque enregistrement, ne peut donc jamais écraser le design.

## 5. Le code expliqué

### 5.1 La table `campaign_experiences`

| Colonne           | Type                                                                    | Rôle                                                      |
| ----------------- | ----------------------------------------------------------------------- | --------------------------------------------------------- |
| `campaign_id`     | `uuid`, **clé primaire**, référence `campaigns(id)` `ON DELETE CASCADE` | Une seule ligne par campagne ; supprimée avec sa campagne |
| `organization_id` | `uuid NOT NULL`, référence `organizations(id)`                          | Sert aux règles d'accès, comme dans les autres tables     |
| `config`          | `jsonb NOT NULL`, `CHECK (jsonb_typeof(config) = 'object')`             | Tout le design du Studio (`ExperienceConfig`)             |
| `updated_at`      | `timestamptz`                                                           | Date lisible de la dernière modification                  |
| `updated_by`      | `uuid`, référence `auth.users(id)` `ON DELETE SET NULL`                 | Qui a fait la dernière modification                       |

Un index sur `organization_id` accélère les règles d'accès.

### 5.2 Les règles d'accès (RLS)

- **Lecture, modification, suppression :** membres de l'organisation seulement (`is_org_member(organization_id)`), comme pour les autres tables.
- **Écriture (insertion et modification) :** en plus, `organization_id` doit être **celui de la campagne**. Sans cette condition, un membre d'Ooredoo pourrait ranger un design sous sa propre organisation mais rattaché à une campagne de Yassir, ou l'inverse. Le script le vérifie dans les deux sens.
- **Aucune règle pour anon.** De plus, `REVOKE ALL … FROM anon` retire le droit de table que les privilèges par défaut de la migration `20260706091000` donnent automatiquement à anon sur toute nouvelle table. Un anonyme reçoit donc « permission denied », pas seulement 0 ligne.

### 5.3 `save_experience_config(p_campaign_id, p_config, p_expected_updated_at)`

`SECURITY INVOKER` : elle s'exécute avec les droits du membre, donc les règles ci-dessus s'appliquent. Étape par étape :

1. `p_config` doit être un objet JSON, sinon `INVALID`.
2. Plus de ~2 Mo → `TOO_LARGE` : un design de cette taille contient encore des images collées dedans (B3.3 les enverra dans Storage).
3. Lecture de la campagne. Si le membre ne la voit pas (autre organisation, ou inexistante) → `NOT_FOUND`. Sinon, on récupère son `organization_id`.
4. **Le serveur fixe `updatedAt` et `campaignId` dans le JSON** : le Studio ne peut ni les inventer ni les falsifier.
5. **Une seule instruction** : `INSERT … ON CONFLICT (campaign_id) DO UPDATE … WHERE p_expected_updated_at IS NULL OR config->>'updatedAt' = p_expected_updated_at`.
   - Pas de ligne → elle est **créée** (1ᵉʳ enregistrement).
   - Une ligne dont la version correspond à celle attendue → elle est **mise à jour**.
   - Une ligne modifiée entre-temps par quelqu'un d'autre → **rien n'est écrit** (0 ligne) → `CONFLICT`. Le Studio sait déjà afficher ce cas (« saved meanwhile in another tab… »).

   `p_expected_updated_at = NULL` signifie « écraser » : ce sera utilisé pour l'import unique des designs du navigateur (B4.3).

6. Renvoie `{ ok: true, config }` avec le design tel qu'enregistré, y compris son nouvel `updatedAt`.

Réservée à `authenticated` et `service_role`.

### 5.4 `get_public_experience(p_slug)`

`SECURITY DEFINER` : c'est volontaire. Un anonyme n'a, et ne doit avoir, aucune règle de lecture sur `campaigns`, `prizes`, `quiz_questions` ni `campaign_experiences`. La fonction lit ces tables pour lui et ne renvoie que des champs sûrs.

| Renvoyé        | Contenu                                                                                                                                                                                            |
| -------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `found`        | `false` si le slug est inconnu, ou si la campagne est `draft` ou `archived` (non publiée)                                                                                                          |
| `campaign`     | `id`, `slug`, `name`, `game_type`, `status`, `rules` (seuils affichables lus dans `game_logic_config`)                                                                                             |
| `prizes`       | lots actifs : `id`, `name`, `win_message`                                                                                                                                                          |
| `quiz`         | questions actives, dans l'ordre : `id`, `question`, `options`                                                                                                                                      |
| `availability` | `{ open: true }`, sinon `{ open: false, reason: "CLOSED" \| "SOLD_OUT" }`. `CLOSED` si la campagne n'est pas `active` **ou** hors de sa période ; `SOLD_OUT` avec la même règle que `select-prize` |
| `experience`   | le design, ou `null` si le Studio n'a jamais été ouvert pour cette campagne                                                                                                                        |

**Jamais renvoyés** (le script le vérifie à toutes les profondeurs du JSON) : `correct_option_index`, `weight`, `quantity`, `quantity_won`, `win_probability`, `max_entries`, `organization_id`, les coupons (`coupon`, `item_value`).

## 6. Décisions et alternatives

| Décision                                            | Alternative écartée                      | Raison                                                                                               |
| --------------------------------------------------- | ---------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Table séparée                                       | Colonne dans `campaigns`                 | Décision D1 du 2026-09-29 (campagne intacte, Wizard sans risque, brouillon possible plus tard)       |
| Contrôle de version sur `config->>'updatedAt'`      | Sur la colonne `updated_at`              | C'est la valeur que le Studio connaît déjà (`storedUpdatedAt`) ; aucune adaptation côté Studio       |
| `get_public_experience` en `SECURITY DEFINER`       | Ouvrir les tables à anon avec des règles | Une règle ouvre des colonnes entières (bonnes réponses, poids) ; la fonction choisit champ par champ |
| `REVOKE ALL … FROM anon` sur la table               | Compter uniquement sur RLS               | Double protection, et une erreur claire au lieu de 0 ligne                                           |
| Campagne `ended` / `paused` → trouvée mais `CLOSED` | → `found: false`                         | Le joueur voit « campagne terminée » avec le design de la marque, au lieu de « introuvable »         |

## 10. Écarts, imprévus et points d'attention

1. **Écart mineur avec le plan :** `save_experience_config` est aussi accordée à `service_role`, en plus d'`authenticated`, pour de futurs scripts d'administration locaux. Sans effet pour les joueurs.
2. **Lecture publique d'une campagne `active` hors période :** elle répond `CLOSED`. `select-prize` accepte encore ces campagnes (il ne vérifie pas la période) : ce sera aligné en B2.1.
3. **Le script `select-prize → 404`** est passé alors que le serveur des Edge Functions avait été arrêté (manque de mémoire, fin de B1.1). Le conteneur `edge_runtime` a donc continué de répondre. Aucune conséquence.
4. **Duplication d'une campagne :** le design n'est pas copié (noté dans `tasks.md` ; après le MVP).

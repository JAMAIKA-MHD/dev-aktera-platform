## 1. Objectif

Sur la page joueur, une campagne en pause, terminée ou dont tous les lots ont été gagnés doit afficher « Campagne terminée » **dès l'ouverture**. Jusqu'ici, le nouveau runtime ne le découvrait qu'**après** le tirage : le joueur remplissait le formulaire pour rien. Le port prévoyait déjà `checkAvailability` : on s'en sert.

## 2. Avant / après

```
Avant : welcome → register (formulaire) → play → tirage → serveur : « fermée » → closed
Après (page publique) : welcome ──checkAvailability : fermée──► closed   (avant le formulaire)
```

La disponibilité vient de `get_public_experience` (B1.2), lue une fois avec la campagne. La passerelle `live` la renvoie sans nouvel appel (B3.2).

## 5. Le code expliqué

### 5.1 L'événement `UNAVAILABLE` (machine d'états, pure)

```ts
| { type: "UNAVAILABLE"; reason: "CLOSED" | "SOLD_OUT" }
```

- **Depuis `welcome` ou `register` seulement** → écran `closed`, avec l'erreur `CAMPAIGN_CLOSED`.
- **Depuis n'importe quel autre écran** (en jeu, tirage en cours, résultat) → rien ne change : c'est la réponse du serveur qui décide.
- **Aucune commande** : aucun tirage n'est déclenché.

L'écran `closed` existant choisit son texte d'après le code d'erreur (« Cette campagne est terminée. Merci de votre intérêt ! » en fr / ar / en). **Aucun nouvel écran, aucun changement visuel.**

### 5.2 `useExperienceFlow`

```ts
const checkOnWelcome = live && state.screen === "welcome";
useEffect(() => { … checkAvailability(campaign.id) → open: false ? dispatch(UNAVAILABLE) … }, [checkOnWelcome]);
```

- La question est posée **à l'arrivée** et **après un « Recommencer »** (retour à l'accueil).
- Une erreur est ignorée : le serveur tranchera au tirage.
- Une réponse arrivée après le démontage du composant est ignorée.

## 6. Décisions et alternatives

| Décision                                   | Alternative écartée                                                      | Raison                                                                                                                                                                                                                                 |
| ------------------------------------------ | ------------------------------------------------------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Passerelle `live` seulement**            | Aussi dans le Studio et le sandbox (fiche : « Profite aussi au Studio ») | Dans le Studio, une campagne en **brouillon** ou en **pause** est justement celle que la marque est en train d'habiller : l'aperçu basculerait sur « terminée » au lieu de montrer l'écran d'accueil. Écart assumé avec la fiche (§10) |
| Réutiliser l'écran `closed` et son message | Un écran « épuisée » à part                                              | Minimum (R6) ; le message dit déjà « campagne terminée »                                                                                                                                                                               |
| Vérifier aussi après « Recommencer »       | Seulement à l'arrivée                                                    | Un joueur qui recommence sur une campagne fermée ne doit pas remplir le formulaire pour rien. Sans coût : la passerelle `live` répond sans appel réseau                                                                                |

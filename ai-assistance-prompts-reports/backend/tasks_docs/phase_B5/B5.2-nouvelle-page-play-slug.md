## 1. Objectif

Les joueurs voient enfin **le design fait dans le Studio**, et jouent avec **le vrai tirage serveur** (`select-prize`). La route `/play/:slug` rend désormais le nouveau runtime (`PlayerExperience`) sur la passerelle `live`, au lieu de l'ancienne page (`PlayerFlowPage`).

## 2. Avant / après

```
Avant : /play/:slug ──► PlayerFlowPage (ancienne page, design violet fixe, repli client)

Après : /play/:slug ──► PublicPlayPage (chargée à la demande)
          loadPublicExperience(slug) ──► rpc get_public_experience ──► parsePublicExperience (zod)
            ├─ not_found ──► « Campagne introuvable » (fr / ar / en)
            ├─ erreur    ──► « Un problème est survenu » + Réessayer

                        <PlayerExperience allowedGatewayModes={["live"]} … />
                      tirage : select-prize · coupon : confirm-coupon · visites : record_campaign_impression
```

L'ancien fichier `PlayerFlowPage.tsx` n'est plus routé ; il sera supprimé en B6.2, après la recette.

## 5. Le code expliqué

### 5.1 `parsePublicExperience(raw)` (domaine, pur)

- **`{ found: false }`** → `{ status: "not_found" }`.
- Sinon, **validation `zod`** de toute la réponse. Une forme inattendue lève une erreur qui cite le champ fautif ; la page affiche alors l'erreur technique.
- **La campagne pour le runtime (`CampaignSnapshot`)** :
  - lots `{ id, name, winMessage }` ;
  - questions `{ id, text, options }`, **sans bonne réponse** (le serveur ne l'envoie pas) ;
  - règles affichables via `rulesFromGameLogic`, **exactement le même calcul que le dashboard** (nombres ou chaînes numériques, valeurs par défaut) ;
  - statut `ended` → `archived`.
- **Le design** :
  - absent (Studio jamais ouvert) → `createDefaultExperience({ campaign })`, le design par défaut de la campagne ;
  - présent → `parseExperienceConfig` (migré, validé, réparé ; problèmes listés dans `configIssues`) ;
  - **fait pour un autre jeu** (type changé dans le Wizard après coup) → seuls les réglages du jeu repartent des valeurs par défaut de la campagne. Le Studio signale le même décalage comme une erreur.

### 5.2 `loadPublicExperience(client, slug)`

`rpc("get_public_experience", { p_slug })`, puis `parsePublicExperience`. Si le serveur est injoignable : exception « Could not load the campaign: … ».

### 5.3 `pickInitialLocale(locales, navigator.languages)`

La première langue du téléphone activée par la marque (`ar-DZ` → `ar`), sinon la langue par défaut de la marque.

### 5.4 `PublicPlayPage`

- **Chargement** : fond sombre plein écran et un indicateur. Aucun texte de marque : le design n'est pas encore connu.
- **`not_found`** : « Campagne introuvable » en fr, ar et en, avec `dir="auto"`, `lang` et la police Poppins / Noto Sans Arabic (règle 5 de `CLAUDE.md`).
- **Erreur** : même présentation, avec « Réessayer · إعادة المحاولة · Retry », qui relance le chargement.
- **`ok`** :
  - `createPublicServices({ client, supabaseUrl, availability })` : passerelle `live`, images Storage, statistiques ;
  - `PlayerExperience` avec `allowedGatewayModes={["live"]}`, **directement dans la page** (jamais dans le `div` d'une autre page) ;
  - titre de l'onglet = nom de la campagne.
- **Campagne fermée ou épuisée** : écran « Campagne terminée » dès l'accueil (B5.1).
- **Chargée à la demande** dans `AppRouter` : le runtime reste hors du bundle du dashboard. La page elle-même pèse 2,8 Ko.

## 6. Décisions et alternatives

| Décision                                                 | Alternative écartée                           | Raison                                                                                                               |
| -------------------------------------------------------- | --------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| Page hors du module, qui n'importe que `index.ts`        | Un composant « page publique » dans le module | Règle du module (ESLint) ; la page est une racine de composition, comme `App.tsx`                                    |
| Réglages du jeu par défaut si le type ne correspond plus | Afficher le design tel quel                   | Un design de quiz sur une campagne roue afficherait un jeu incohérent                                                |
| Extraire `rulesFromGameLogic`                            | Dupliquer la lecture des seuils               | Un seul calcul, donc le joueur et le dashboard affichent les mêmes seuils (écart minime dans une zone protégée, §10) |
| Messages de la page en fr / ar / en en même temps        | Choisir une langue                            | Le design (et ses langues) n'est pas encore connu à ce moment                                                        |

## 10. Écarts, imprévus et points d'attention

1. **Zone protégée (domaine)** : `campaign.ts` a une fonction exportée en plus (`rulesFromGameLogic`), extraite sans changer le calcul (rules §3.2 : nécessaire, minime, documentée).
2. **Balayage responsive (`xp:responsive`) non relancé sur `/play/:slug`** : la page affiche le même runtime que `/xp-frame`, déjà balayé à toutes les tailles. La machine n'avait plus que 2 Go de mémoire libre. À faire en B6.1, sur une vraie campagne.
3. **L'ancienne page et son repli client existent encore dans le code** (non routés) : suppression en B6.2, avec les lectures anonymes directes des tables.
4. **Mise en ligne** : cette page doit être déployée **avant** la nouvelle version de `select-prize` (B6.3). Elle sait lire les anciens messages d'erreur (B3.2).
5. **`import.meta.env?.DEV`** dans le traceur : sans effet dans le navigateur ; évite une erreur quand le module est chargé hors de Vite (scripts de vérification).

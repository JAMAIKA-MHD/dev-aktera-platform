# T1.4 — Tirage : exclure un lot à codes épuisé

> Phase P1 · voir `../tasks.md`, `../plan.md`, `../rules.md`.

**Statut :** [ ] à faire

## Objectif

Empêcher de déclarer gagnant d'un code qui n'existe plus (plan §4.3). Un lot sans aucun code reste éligible.

## Fichiers concernés

- `supabase/migrations/<timestamp>_reward_expiry_and_delivery.sql`
- `migration source du tirage notée en T0.1`

## Étapes

1. Recopier `draw_and_claim_campaign_prize` à l'identique depuis la source notée en T0.1.
2. Dans **les deux** boucles de candidats, ajouter une condition d'éligibilité : le modèle du lot n'a **aucun** item (`NOT EXISTS prize_template_items`) **ou** il existe au moins un item pour lequel `is_code_assignable(id)` est vrai.
3. Ne pas changer la signature, le type de retour, ni les `GRANT` (le tirage reste exécutable comme avant).
4. Si le tirage est déjà redéfini ailleurs, appliquer la règle à la version la plus récente et le noter.

## Vérification

Test de T1.7 : lot dont tous les codes sont utilisés/expirés jamais tiré (≥ 200 tirages) ; lot sans code toujours tirable.

## Critères de fin

- [ ] Un lot à codes épuisé n'est jamais désigné gagnant.
- [ ] Un lot sans code reste éligible.
- [ ] Les autres règles (poids, quotas auto-pace, période) sont inchangées.

# T1.5 — RPC `set_entry_delivery_status`

> Phase P1 · voir `../tasks.md`, `../plan.md`, `../rules.md`.

**Statut :** [x] fait

## Objectif

Seul chemin pour changer le statut de livraison, avec tous les contrôles côté serveur.

## Fichiers concernés

- `supabase/migrations/<timestamp>_reward_expiry_and_delivery.sql`

## Étapes

1. Créer `public.set_entry_delivery_status(p_entry_id uuid, p_status text) RETURNS void`, `SECURITY DEFINER`, `SET search_path = public`.
2. Contrôles dans l'ordre : `auth.uid()` non nul ; `p_status` dans (`not_delivered`, `delivered`) ; entrée trouvée et `is_winner = true` ; lot lié de catégorie `physical` (`entries.prize_id → prizes → prize_templates`) ; appelant a un profil dans `entries.organization_id` ; rôle ≠ `viewer`.
3. `UPDATE entries SET delivery_status = p_status, delivered_at = CASE WHEN p_status = 'delivered' THEN now() END WHERE id = p_entry_id`.
4. Un message d'erreur distinct par refus (non connecté / statut invalide / entrée introuvable / pas un lot physique / non autorisé).
5. `REVOKE ALL … FROM PUBLIC, anon, authenticated;` puis `GRANT EXECUTE … TO authenticated;`.

## Vérification

Test de T1.7 : membre OK, `viewer` refusé, autre organisation refusée, entrée perdante refusée, lot numérique refusé, `anon` refusé.

# T2.1 — select-prize : marquer une attribution manquée

> Phase P2 · voir `../tasks.md`, `../plan.md`, `../rules.md`.

**Statut :** [x] fait

## Objectif

Quand un lot à codes gagne mais qu'aucun code n'a pu être attribué (course sur le dernier code), le signaler pour la marque, sans changer la réponse au joueur.

## Fichiers concernés

- `supabase/functions/select-prize/index.ts`

## Étapes

1. Après `claimCoupon` (étape 10) : si `isWinner` et le lot **a des codes** (au moins un `prize_template_items` pour son modèle) et que le code renvoyé est `null`, mettre à jour l'entrée : `metadata = metadata || { reward_unavailable: true }` et `console.warn` avec l'id de l'entrée.
2. Si le lot n'a aucun code : ne rien faire (le « You Won! » sans récompense continue de marcher).
3. Ne changer ni les codes d'erreur, ni la forme de la réponse JSON, ni le rejeu par `client_request_id`.
4. Garder la requête de vérification la plus simple possible (un `count` limité à 1).

## Vérification

`npx tsc`/lint de la fonction si configuré ; test manuel en T2.2.

## Critères de fin

- [x] Le marquage n'a lieu que pour un lot à codes sans code attribué.
- [x] La réponse au joueur est identique à avant.

## 1. Objectif

Le tiroir « Interactive Player Sandbox » (Portal Simulator) du tableau de bord jouait les anciens écrans (`PlayerLanding`, `PlayerGame`… dans un `PhoneFrame`), habillés par des couleurs devinées d'après le nom de la marque. Il joue désormais **le vrai runtime**, dans son propre document, à la taille d'un téléphone, avec ce que la marque a réglé dans le Studio.

## 5. Le code expliqué

### 5.1 `CampaignSimulator`

```tsx
<CampaignSimulator
  campaigns={campaigns}
  prizeTemplates={prizes}
  campaignId={sandboxCampaignId || null}
/>
```

- Construit le snapshot de la campagne (`buildCampaignSnapshot`, comme `CampaignStudio`) ; sans campagne, ou avec « Default experience », le runtime joue la campagne de démonstration.
- Crée un **store du Studio** pour ce que lit `PreviewViewport` : la configuration **enregistrée** par le Studio est chargée (`loadIntoStudio`, le même chemin que le Studio), l'écran part de l'accueil, en mode `demo` (passerelle de démonstration).
- L'appareil est **toujours** l'iPhone 12-14 (390 × 844, zoom « fit ») : jamais l'appareil mémorisé par le Studio (tablette, paysage…), et rien n'est jamais écrit depuis le tiroir (pas d'autosave, pas de préférences).
- Une session par campagne (`key`) : changer de campagne repart de zéro, sans rien garder du parcours précédent ; la campagne rechargée pendant que le tiroir est ouvert met les données à jour sans relancer.
- « Play again » relance le parcours (`restartKey`, comme le bouton Restart du Studio).

### 5.2 Le tiroir d'`App.tsx`

- Même tiroir (animation, largeur 390-410 px), aux couleurs du tableau de bord (jetons `card-bg`, `card-border`…) au lieu du `slate-900` codé en dur ; `role="dialog"`, `aria-label` sur le sélecteur et la fermeture.
- Le sélecteur propose « Default experience (demo campaign) » et les campagnes non archivées ; il partage `sandboxCampaignId` avec le Studio (la campagne ouverte dans l'un est celle de l'autre).
- **Supprimés** : les 8 imports des anciens écrans (`PhoneFrame`, `PlayerLanding`, `PlayerGame`, `PlayerQuiz`, `PlayerScratch`, `PlayerMysteryBox`, `PlayerHitIt`, `PlayerResult`), `LOSER_SLOT`, `mapCampaignToBrandPreset` et ses couleurs par nom de marque (Djezzy, Yassir, Hamoud, Soummam), `sandboxScreen`, `sandboxPlayerData`, `sandboxSelectedPrize`, `handleSandboxRegister/GameComplete/Restart`, et les sept écrans animés du tiroir.

## 6. Décisions et alternatives

| Décision                                              | Alternative écartée                           | Raison                                                                             |
| ----------------------------------------------------- | --------------------------------------------- | ---------------------------------------------------------------------------------- |
| Réutiliser `PreviewViewport` avec un store du Studio  | Un second composant d'iframe propre au tiroir | Une seule façon d'afficher le runtime (taille CSS réelle, zoom, pont, zones sûres) |
| Appareil fixe 390 × 844                               | L'appareil mémorisé par le Studio             | Critère de la fiche ; le tiroir fait 375 à 410 px, un téléphone y a sa place       |
| Pas de barre d'appareils ni de langues dans le tiroir | Toute la barre d'aperçu du Studio             | Le tiroir sert à **jouer** ; régler la présentation se fait dans le Studio         |
| Couleurs du tableau de bord                           | Garder le fond `slate-900`                    | Le pied de `PreviewViewport` (taille, zoom) utilise les jetons du tableau de bord  |

## 9. Écarts, imprévus et points d'attention

- **Chances du simulateur** : comme l'aperçu du Studio (noté en T7.1), la passerelle de démo joue avec des chances reconstruites du snapshot, pas avec la probabilité et les poids réels. Proposé pour l'après-MVP.

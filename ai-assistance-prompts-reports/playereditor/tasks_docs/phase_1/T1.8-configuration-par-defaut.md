## 1. Objectif

Quand une marque ouvre le Studio pour une campagne, l'écran doit être **complet et beau dès la première seconde**, sans rien remplir. T1.8 assemble les briques de T1.7 en une configuration entière, adaptée au jeu et aux lots de la campagne.

Quatre pièces :

| Pièce                                        | Rôle                                                                                  |
| -------------------------------------------- | ------------------------------------------------------------------------------------- |
| `createDefaultExperience`                    | Construit la configuration complète (style, textes, sections, formulaire, légal, jeu) |
| `buildDefaultWheelSegments`                  | Construit la roue à partir des lots de la campagne                                    |
| `buildCampaignSnapshot`                      | Traduit la campagne du tableau de bord en « ce que le joueur a le droit de savoir »   |
| `resolvePrizeDisplay`, `resolveQuizQuestion` | Décident du texte affiché pour un lot ou une question, dans la langue du joueur       |

Et une **campagne de démonstration** fixe, utilisée quand le Studio s'ouvre sans vraie campagne.

## 5. Le code expliqué

### 5.1 `createDefaultExperience` : une configuration prête à montrer

```ts
createDefaultExperience({ gameType, campaign?, presetId?, brandName? })
```

| Partie                    | Valeur par défaut                                                                                                        |
| ------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| Style                     | `themeFromPreset(presetId)` : Midnight Gold si absent ou inconnu                                                         |
| Écrans                    | `defaultScreens(jeu)` : textes fr/ar/en propres au jeu (T1.7)                                                            |
| Sections                  | Bloc jackpot **activé** ; 3 pastilles de lots **activées**                                                               |
| Formulaire                | Nom (obligatoire), téléphone (obligatoire), email (désactivé), wilaya (facultative), avec libellés et exemples de saisie |
| Consentement              | Texte loi 18-07, version de politique `2026-09-01`                                                                       |
| Légal                     | Organisateur = nom de la marque ; liens Règlement, Confidentialité, Assistance ; mention courte ; règlement complet      |
| Jeu                       | Accroche animée, légende automatique (`caption: null`) ; réglages propres au jeu (§5.2)                                  |
| Lots, traductions du quiz | Vides : les données de la campagne s'appliquent (§5.4)                                                                   |
| Options                   | Son et animations activés ; bonus de partage verrouillé à `false`                                                        |

Trois choix importants :

1. **La campagne décide du jeu.** Si une vraie campagne est fournie, c'est son type de jeu qui compte (il a été choisi dans le Wizard) ; `gameType` ne sert que sans campagne.
2. **Sans campagne, la démo.** La configuration est construite sur la campagne de démonstration (§5.5), mais `campaignId` reste `null` : la configuration n'est liée à aucune campagne réelle.
3. **Copie profonde finale** (`structuredClone`). Sans elle, modifier un titre dans le Studio aurait modifié le texte par défaut partagé, et donc toutes les configurations suivantes. Un test le vérifie.

Chaque élément de liste (pastilles, liens, segments) reçoit son propre identifiant unique.

`createDefaultExperience` reste la **valeur de secours** de `parseExperienceConfig` (T1.6) : un champ abîmé est désormais réparé par un vrai texte, plus par un texte vide.

### 5.2 La roue construite à partir des lots

`buildDefaultWheelSegments(prizes)` :

- un segment par lot, dans l'ordre de la campagne, et **au moins un segment perdant** ;
- **4 segments minimum** : avec moins de 3 lots, des segments perdants complètent la roue ;
- **12 segments maximum** : au-delà de 11 lots, les lots suivants n'ont pas de segment ;
- les segments perdants sont **répartis** autour de la roue, avec des libellés variés (« Dommage », « Presque ! », « Pas cette fois ») ;
- les couleurs restent `null` : c'est le rendu qui alternera les couleurs du thème, pour qu'un changement de style recolore la roue.

| Nombre de lots | Roue (P = lot, L = perdu)    |
| -------------- | ---------------------------- |
| 0              | L L L L                      |
| 1              | L P L L                      |
| 2              | P L P L                      |
| 3              | P P P L                      |
| 5              | P P P P P L                  |
| 11             | 11 × P, puis L               |
| 15             | les 11 premiers lots, puis L |

**La roue n'influence jamais le résultat** (règle N1). Le serveur tire au sort ; la roue ne fait que s'arrêter sur le segment du lot gagné, ou sur un segment perdant.

Les autres jeux :

| Jeu             | Réglages par défaut                                              |
| --------------- | ---------------------------------------------------------------- |
| Carte à gratter | Texte « Grattez ici », révélation à 50 %                         |
| Boîtes mystère  | 3 boîtes, icône cadeau                                           |
| Quiz            | Aucune traduction : les questions s'affichent telles que saisies |
| Hit It          | Cible : icône « target »                                         |

### 5.3 `buildCampaignSnapshot` : ce que le joueur a le droit de savoir

La campagne du tableau de bord (`Campaign`, lue par `useCampaigns`) contient des **secrets du tirage** : poids, quantités, stock gagné, probabilité de gain, bonnes réponses. Le snapshot n'en garde **aucun** :

| Snapshot                           | Source                                                      |
| ---------------------------------- | ----------------------------------------------------------- |
| `id`, `name`, `gameType`, `status` | Copiés tels quels                                           |
| `prizes[].name`                    | **Nom du modèle de lot** (voir ci-dessous)                  |
| `prizes[].winMessage`              | `null` (voir ci-dessous)                                    |
| `quiz`                             | Questions et options, dans l'ordre, **sans `correctIndex`** |
| `rules`                            | Lues dans `game_logic_config`, avec les défauts de la RPC   |

**Imprévu : les lots de `Campaign` n'ont pas de nom.** Le type ne contient que `templateId`, `quantity` et `weight`. En base, la fonction d'enregistrement copie le nom du **modèle de lot** dans `prizes.name` (`v_template_record.name`). `buildCampaignSnapshot` prend donc un second paramètre, la liste des modèles (`usePrizeTemplates`), et retrouve le nom par `templateId`. Un modèle introuvable donne un nom vide. `win_message` n'est pas chargé par `useCampaigns` : il vaut `null`.

Un lot **sans identifiant** (pas encore enregistré) est ignoré : le serveur ne pourrait jamais le renvoyer comme gain.

**Règles** (règles publiques, affichées au joueur, par exemple « 8 touches en 10 s ») :

| Règle                     | Clé de `game_logic_config`  | Défaut          | Origine du défaut          |
| ------------------------- | --------------------------- | --------------- | -------------------------- |
| Seuil de réussite du quiz | `pass_threshold_percentage` | 100             | RPC `resolve_game_outcome` |
| Secondes par question     | `quiz_seconds_per_question` | 0 (sans chrono) | Plan §12.2                 |
| Seuil de Hit It           | `win_threshold`             | 1               | RPC `resolve_game_outcome` |
| Durée de Hit It           | `hit_it_duration_seconds`   | 10              | Plan §12.2                 |

Comme la RPC, la lecture accepte un nombre ou une chaîne numérique (`"8"`). Une valeur illisible (`""`, `"x"`, configuration qui n'est pas un objet) donne le défaut. Seules les règles du jeu concerné sont présentes : la roue, la carte et les boîtes n'en ont pas (le tirage seul décide).

### 5.4 L'affichage d'un lot et d'une question (`display.ts`)

**`resolvePrizeDisplay(prizeId, config, campaign, langue)`**, dans cet ordre :

1. l'affichage choisi par la marque dans le Studio (`config.prizeDisplay`), dans la langue du joueur, sinon dans la langue par défaut de la configuration ;
2. sinon le nom et le message de la campagne ;
3. sinon une chaîne vide (libellé) ou `null` (message).

**`resolveQuizQuestion(question, config, langue)`** :

| Situation                                  | Résultat                                                       |
| ------------------------------------------ | -------------------------------------------------------------- |
| Pas de traduction                          | Texte de la base, `outdated: false`                            |
| Traduction à jour, langue traduite         | Texte traduit ; chaque option traduite, sinon celle de la base |
| Traduction à jour, langue **non** traduite | Texte de la base (jamais une autre langue)                     |
| Traduction **périmée**                     | Texte de la base, `outdated: true`                             |

**L'ordre des options n'est jamais modifié.** Le joueur répond par un **numéro d'option**, que le serveur compare à la bonne réponse enregistrée en base. Réordonner les options, même en traduction, fausserait la correction.

**Traduction périmée.** Chaque traduction garde une **empreinte** (`sourceHash`) du texte d'origine et de ses options. Si la marque modifie ensuite la question dans le Wizard, l'empreinte ne correspond plus : la traduction est ignorée, et `outdated: true` permettra au Studio de le signaler (T6.11). L'empreinte (`quizSourceHash`) est un calcul FNV-1a sur 32 bits, déterministe et synchrone. Ce n'est pas une protection de sécurité, seulement un détecteur de changement.

### 5.5 La campagne de démonstration (`presets/demoCampaign.ts`)

`createDemoCampaign(jeu)` : identifiant fixe `demo-campaign`, 4 lots (bon d'achat 2000 DA, casque sans fil, réduction de 20 %, coffret cadeau), 3 questions de culture générale sur l'Algérie, règles par défaut. Les identifiants sont **stables** : une configuration enregistrée sur la démo garde ses réglages d'affichage des lots.

Les textes de la démo sont en français seulement, comme les données qu'une marque saisit dans le Wizard. Les bonnes réponses ne sont pas là : la passerelle de démonstration (phase 2) en aura besoin, elle les définira de son côté.

### 5.6 Une exception assumée à la règle « le domaine n'importe rien »

`domain/defaults.ts` lit `presets/contentDefaults.ts`, `themePresets.ts` et `demoCampaign.ts`. Le plan le prévoit (§ « `domain/defaults.ts` … s'appuyant sur `presets/*` »), mais son tableau §4.3 dit que le domaine n'importe rien. Ces trois fichiers sont de la **donnée pure**, sans React. Pour que l'exception reste sûre :

- une règle ESLint interdit au domaine d'importer `lucide-react` et `presets/icons.ts` (le seul fichier React des presets) ; vérifiée avec un fichier temporaire (1 erreur attendue, 1 obtenue) ;
- le README du module précise la règle.

## 6. Décisions et alternatives

| Décision                                          | Alternative écartée                                    | Raison                                                                                              |
| ------------------------------------------------- | ------------------------------------------------------ | --------------------------------------------------------------------------------------------------- |
| `buildCampaignSnapshot(campaign, prizeTemplates)` | `buildCampaignSnapshot(campaign)`, comme dans la fiche | Les lots de `Campaign` n'ont pas de nom ; la base le copie du modèle                                |
| Lots non enregistrés ignorés                      | Identifiant fabriqué à partir du modèle                | Un faux identifiant ne correspondrait jamais au lot renvoyé par le serveur                          |
| La campagne fournie décide du jeu                 | `gameType` décide                                      | Le jeu est choisi dans le Wizard ; une divergence produirait une roue sans réglages                 |
| Couleurs des segments à `null`                    | Couleurs calculées maintenant                          | Un changement de style doit recolorer la roue                                                       |
| Segments perdants répartis                        | Tous à la fin                                          | Roue plus équilibrée visuellement                                                                   |
| Pas de repli sur une autre langue pour le quiz    | Chaîne de repli de `resolveText`                       | Une question affichée dans la mauvaise langue est pire que le texte d'origine                       |
| Empreinte FNV-1a synchrone                        | SHA-256 (`crypto.subtle`)                              | `crypto.subtle` est asynchrone et absent hors contexte sécurisé ; un détecteur de changement suffit |
| Copie profonde de la configuration                | Faire confiance au Studio pour ne pas muter            | Défense peu coûteuse contre un bug très difficile à trouver                                         |

## 9. Écarts, imprévus et points d'attention

- **Signature de `buildCampaignSnapshot` élargie** (§5.3) : second paramètre, les modèles de lots.
- **`win_message` absent du tableau de bord** : `useCampaigns` ne le charge pas. Le message de gain de la campagne n'apparaîtra donc pas dans l'aperçu du Studio tant que la requête n'est pas étendue (hors périmètre : `src/hooks/` n'appartient pas au module). La page publique `/play/:slug` le charge déjà.
- **Plus de 11 lots** : les lots en trop n'ont pas de segment. Si le serveur fait gagner l'un d'eux, la roue devra le gérer (s'arrêter sur un segment neutre, puis afficher le lot). **À traiter en T5.2** (roue).
- **Seuil de Hit It à 1 par défaut** : c'est la valeur de la RPC. L'accroche afficherait « 1 touches en 10 s » : l'accord au singulier est à gérer dans le calcul de la légende (`autoCaption`, T5.1).
- **Exception de dépendance** `domain/` → presets de données (§5.6), protégée par ESLint.
- **Test de T1.6 modifié** : `schema.test.ts` attendait l'ancien libellé central vide de la roue ; il attend maintenant le libellé par défaut (« JOUER »). C'est le comportement voulu : un champ réparé reçoit un vrai texte.

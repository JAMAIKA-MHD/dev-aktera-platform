## 1. Objectif

Poser le socle multilingue du contenu joueur. Chaque texte vu par un joueur (titre, bouton, message de gain…) peut exister en **français, arabe et anglais**. Ce fichier fournit la **seule** façon, testée, de :

- choisir la bonne langue ;
- se replier proprement quand une traduction manque ;
- savoir quelles traductions manquent ;
- connaître le sens d'écriture (l'arabe s'écrit de droite à gauche).

C'est le **premier fichier du domaine** : du TypeScript pur, sans React, sans stockage, entièrement testé.

## 5. Le code expliqué

### Les types

```ts
export type Locale = "fr" | "ar" | "en";

export const LOCALES: readonly Locale[] = ["fr", "ar", "en"];

export type LocalizedText = Partial<Record<Locale, string>>;
```

- **`Locale`** : les trois langues du contenu joueur, par leur code ISO 639-1.
- **`LOCALES`** : la même liste, utilisable à l'exécution (boucles, sélecteurs de langue). Le français vient en premier, c'est la langue par défaut du marché.
- **`LocalizedText`** : un objet avec au plus une valeur par langue, par exemple `{ fr: "Lancer le jeu", ar: "ابدأ اللعب الآن" }`. `Partial` rend chaque langue **facultative** : un texte peut n'être traduit qu'en français. C'est normal pendant la saisie, et c'est exactement ce que gère le repli.

### Ce qui compte comme « rempli »

```ts
// Whitespace-only values count as missing, so a field left with spaces falls back like an empty one.
function isFilled(value: string | undefined): value is string {
  return value !== undefined && value.trim() !== "";
}
```

Fonction interne, non exportée. Une valeur **vide ou faite uniquement d'espaces** compte comme absente. Sans cette règle, un marketeur qui laisse un espace dans le champ arabe ferait apparaître un titre vide aux joueurs arabophones, au lieu du texte français de repli.

`value is string` est un **prédicat de type** : après `if (isFilled(value))`, TypeScript sait que `value` est une `string`, sans conversion.

### `resolveText` : choisir le texte à afficher

```ts
// Fallback chain: requested locale → configured default → fr → en → any remaining locale.
// Never returns undefined: a text missing everywhere resolves to "".
export function resolveText(
  text: LocalizedText | undefined,
  locale: Locale,
  fallback?: Locale,
): string {
  if (!text) return "";
  const chain: Locale[] = fallback ? [locale, fallback] : [locale];
  chain.push("fr", "en", ...LOCALES);
  for (const candidate of chain) {
    const value = text[candidate];
    if (isFilled(value)) return value;
  }
  return "";
}
```

C'est la fonction la plus utilisée du module. Elle construit une **chaîne de repli** et renvoie la première valeur remplie :

| Rang | Langue essayée                                                                   | Pourquoi                                                            |
| ---- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------- |
| 1    | `locale` : la langue du joueur                                                   | Le cas normal                                                       |
| 2    | `fallback` : la langue par défaut de la configuration (`config.locales.default`) | Choix de la marque                                                  |
| 3    | `fr`                                                                             | Langue principale du marché algérien                                |
| 4    | `en`                                                                             | Dernier repli « international »                                     |
| 5    | `...LOCALES`, donc `ar` en pratique                                              | Dernier recours : afficher le seul texte qui existe plutôt que rien |

**Exemples :**

| Texte                            | Joueur    | Défaut | Résultat                                                   |
| -------------------------------- | --------- | ------ | ---------------------------------------------------------- |
| `{ fr: "Bonjour", ar: "مرحبا" }` | `ar`      | —      | `"مرحبا"`                                                  |
| `{ fr: "Bonjour", en: "Hello" }` | `ar`      | `en`   | `"Hello"` (le défaut de la marque passe avant le français) |
| `{ fr: "Bonjour", ar: "  " }`    | `ar`      | —      | `"Bonjour"` (les espaces comptent comme vide)              |
| `{ ar: "مرحبا" }`                | `en`      | `fr`   | `"مرحبا"` (dernier recours)                                |
| `{}` ou `undefined`              | n'importe | —      | `""`                                                       |

**Détails de conception :**

- Une langue peut apparaître deux fois dans la chaîne (par exemple si `fallback` vaut `fr`). C'est sans effet : la première occurrence renvoie déjà la valeur. Il n'y a donc pas besoin de dédoublonner.
- **La fonction ne renvoie jamais `undefined`** (demandé par la fiche). Les composants peuvent afficher le résultat sans vérification.
- **La valeur est renvoyée telle quelle, sans suppression des espaces** : on ne modifie jamais le texte saisi par la marque ; on décide seulement s'il est vide.
- Seules les trois langues connues sont lues. Une clé étrangère éventuelle dans un fichier importé (par exemple `de`) est ignorée ; le schéma zod de T1.6 la supprimera.

### `hasText` et `missingLocales` : savoir ce qui manque

```ts
export function hasText(
  text: LocalizedText | undefined,
  locale: Locale,
): boolean {
  return isFilled(text?.[locale]);
}

export function missingLocales(
  text: LocalizedText | undefined,
  enabled: readonly Locale[],
): Locale[] {
  return enabled.filter((locale) => !hasText(text, locale));
}
```

- **`hasText`** répond à « ce texte existe-t-il dans **cette** langue ? », sans repli. `text?.[locale]` tolère un texte absent (`undefined`).
- **`missingLocales`** renvoie les langues **activées par la marque** qui n'ont pas de texte, **dans l'ordre fourni**. Le Studio s'en servira pour afficher « AR: missing translation » ; la validation, pour ses avertissements. On ne compare qu'aux langues activées : si la marque n'a pas activé l'anglais, l'absence d'anglais n'est pas un problème.

### `getDirection` : le sens d'écriture

```ts
export function getDirection(locale: Locale): "rtl" | "ltr" {
  return locale === "ar" ? "rtl" : "ltr";
}
```

`rtl` (droite à gauche) pour l'arabe, `ltr` pour le reste. T3.1 posera cette valeur sur l'attribut `dir` de la racine du runtime. Tout l'écran se retourne alors en arabe (ordre des éléments, alignements), avec la police _Noto Sans Arabic_ (règle N5).

### `localized` : écrire les textes par défaut

```ts
// Builds preset content without undefined keys, so it serializes to clean JSON.
export function localized(fr: string, ar?: string, en?: string): LocalizedText {
  const text: LocalizedText = { fr };
  if (ar !== undefined) text.ar = ar;
  if (en !== undefined) text.en = en;
  return text;
}
```

Un raccourci pour les fichiers de contenu (T1.7) : `localized("Lancer le jeu", "ابدأ اللعب الآن", "Start playing")`. Le français est obligatoire (langue par défaut) ; l'arabe et l'anglais sont facultatifs.

**Pourquoi ne pas écrire simplement `{ fr, ar, en }` ?** Parce qu'avec `ar` absent, cet objet contiendrait `ar: undefined`. `JSON.stringify` l'effacerait, mais l'objet en mémoire et l'objet relu seraient alors **différents** : les comparaisons, l'historique d'annulation et le schéma zod en seraient perturbés. `localized` ne crée que les clés réellement fournies.

## 6. Décisions et alternatives

| Décision                                                                      | Alternative écartée                    | Raison                                                                                                                                                                                                                                                           |
| ----------------------------------------------------------------------------- | -------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `LOCALES: readonly Locale[]`, et `missingLocales` accepte `readonly Locale[]` | `Locale[]`, comme écrit dans la fiche  | Une liste exportée modifiable pourrait être altérée par erreur (`LOCALES.push`) et changer tout le module. `readonly` l'interdit à la compilation, et un `Locale[]` classique reste accepté partout. Le type est donc plus strict que la fiche, sans rien casser |
| Les espaces seuls comptent comme vide                                         | Seule la chaîne `""` compte comme vide | Un champ laissé avec des espaces afficherait un titre vide au joueur                                                                                                                                                                                             |
| La valeur est renvoyée sans suppression des espaces                           | Renvoyer `value.trim()`                | Ne jamais modifier le texte saisi par la marque                                                                                                                                                                                                                  |
| « Première valeur non vide » = parcours de `LOCALES`                          | Parcours des clés de l'objet           | L'ordre des clés d'un objet JSON dépend de sa construction. Suivre `LOCALES` rend le résultat **déterministe** et ignore les langues inconnues                                                                                                                   |
| Pas de fonction `isLocale()`                                                  | L'ajouter dès maintenant               | Utile plus tard (schéma, paramètre d'URL), mais hors de la fiche (règle R5). Elle viendra avec la tâche qui en aura besoin                                                                                                                                       |

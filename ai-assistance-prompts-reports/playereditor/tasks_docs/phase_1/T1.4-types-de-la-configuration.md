## 1. Objectif

Écrire le **modèle de données central** de toute la refactorisation :

- **`ExperienceConfig`** : tout ce que la marque personnalise dans le Studio (style, textes, formulaire, légal, présentation du jeu). C'est ce qui sera sauvegardé, exporté, envoyé à l'aperçu, et plus tard stocké en base ;
- **`CampaignSnapshot`** : ce que le runtime (l'écran du joueur) sait de la campagne.

Ces deux types sont le **contrat** entre le Studio, le runtime, le stockage et, plus tard, le serveur. Toutes les tâches suivantes les utilisent.

## 5. Le code expliqué

### Principe général

```ts
// Everything in this file is plain JSON: no functions, no React nodes, no Date objects
// (types.test.ts fails otherwise). Behavior lives in the flow state machine, not here.
```

La configuration est **une donnée, pas du code** (règle A2). Elle ne contient que des textes, des nombres, des booléens, des listes et des objets. C'est ce qui lui permet d'être enregistrée dans `localStorage`, exportée en fichier, envoyée à l'iframe d'aperçu par `postMessage`, et plus tard stockée dans la colonne JSONB `campaigns.player_screen_config`. Le commentaire en tête du fichier le rappelle, et un test le **garantit** (§7).

### Les types de `types.ts`, un par un

| -------------------------------------------------- | -------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |

| `AssetRef`                                         | Référence à une image                  | 4 formes : fichier importé (`dataUrl`, MVP), lien `https` (`remote`), Supabase Storage (`storage`, après le MVP), ou `null` (pas d'image). ### `GameSettings` : de la présentation, jamais des règles

```ts
// Game PRESENTATION only. Rules that decide a win (prizes, weights, stock, win probability,
// questions and correct answers, thresholds, durations) live in the campaign, never here.
export interface GameSettings {
  type: GameType; // = the campaign game type, chosen in the Wizard
  teaser: {
    mode: "attract" | "static"; // animated pregame simulation or still image
    caption: LocalizedText | null; // null = caption generated from the campaign
  };
  wheel?: {
    segments: WheelSegment[]; // 4 to 12, all the same visual size
    hubLabel: LocalizedText;
  };
  scratch?: {
    coverImage: AssetRef;
    coverText: LocalizedText;
    revealThresholdPercent: number;
  };
  boxes?: { count: 3; icon: IconName; color: string | null };
  quiz?: {
    // Display translations of the campaign questions, keyed by quiz_questions.id.
    // Never contains the correct answer.
    translations: Record<string, QuizQuestionTranslation>;
  };
  hitIt?: { targetIcon: IconName; targetImage: AssetRef };
}
```

C'est l'application directe de la décision n° 14 et du plan §6.6 : **ce qui décide qui gagne n'est pas ici**. Seuils, durées, poids, bonnes réponses : tout cela vit dans la campagne, où le serveur le lit.

- **Un bloc par jeu, facultatif (`?`)** : une campagne « roue » n'a que `wheel`. Les autres blocs sont absents.
- **`boxes.count: 3`** est un **type littéral** : il ne peut valoir que 3. La mécanique à 3 boîtes est fixe dans le MVP, et le type l'exprime.
- **`quiz.translations`** est indexé par l'identifiant de la question en base, et ne contient que du texte.
- **`revealThresholdPercent`** (la part du ticket à gratter avant la révélation) reste ici : ce n'est pas une règle de gain, puisque pour le grattage le lot est **déjà tiré** avant que le joueur gratte.

### `ExperienceConfig` : l'ensemble

```ts
export interface ExperienceConfig {
  schemaVersion: 1;
  id: string; // UUID
  campaignId: string | null; // null = standalone (demo campaign)
  templateId: "eight-slot"; // single template in the MVP
  updatedAt: string; // ISO 8601
  locales: { default: Locale; enabled: Locale[] };
  theme: ThemeTokens;
  brand: {
    name: string;
    logo: AssetRef;
    logoIcon: IconName;
    tagline: LocalizedText;
  };
  screens: Record<ScreenKey, ScreenContent>;
  sections: { jackpot: JackpotSection; prizeChips: PrizeChipsSection };
  form: FormConfig;
  legal: LegalConfig;
  game: GameSettings;
  prizeDisplay: Record<string, PrizeDisplay>; // keyed by prizes.id
  features: {
    sound: boolean;
    animations: boolean;
    shareBonus: false; // locked: "+1 try for a share" stays off until the server can verify shares
  };
}
```

- **`schemaVersion: 1`** : littéral. Quand le format changera, une version 2 et une migration (T1.9) permettront de relire les anciennes configurations sans les casser.
- **`updatedAt` est une chaîne ISO 8601, pas un `Date`** : un `Date` ne survit pas à un passage en JSON (il redevient une chaîne). Il sert aussi au contrôle de conflit entre deux onglets (T2.2).
- **`screens: Record<ScreenKey, ScreenContent>`** : TypeScript exige les **5** écrans ; impossible d'en oublier un.
- **`shareBonus: false`** : type littéral `false`. Le « +1 essai contre un partage » **ne peut pas** être activé dans une configuration, même par erreur, tant que le type n'aura pas été changé volontairement (décision n° 6, règle N4).

### `campaign.ts` : `CampaignSnapshot`

```ts
// What the runtime knows about a campaign. Never contains weights, stock, win probability,
// coupon codes or correct answers: those only reach the demo gateway, or stay on the server.
export interface CampaignSnapshot {
  id: string;
  name: string;
  gameType: GameType;
  status: CampaignStatus;
  prizes: CampaignPrize[];
  quiz: CampaignQuizQuestion[]; // sorted by position
  rules: CampaignRules;
}
```

- **Ce qui n'y est pas compte autant que ce qui y est** (règle B2) : ni poids, ni stock, ni probabilité, ni code, ni bonne réponse. Même si un joueur inspectait la mémoire de la page, il n'y trouverait rien qui l'aide à gagner.
- **`CampaignQuizQuestion.options`** garde l'ordre de la base : les réponses sont envoyées au serveur **par index** dans cette liste (règle B10). Une traduction ne change donc jamais la réponse envoyée.
- **`CampaignRules`** (`QuizRules`, `HitItRules`) : les règles **publiques**, qu'on peut afficher au joueur (« 8 touches en 10 s »). Elles viennent de `campaigns.game_logic_config`, les mêmes valeurs que lit le serveur.

### `index.ts` : l'API publique

```ts
export type { ExperienceConfig } from "./domain/types";
export type { CampaignSnapshot } from "./domain/campaign";
```

La ligne en commentaire prévue en T0.3 pour T1.4 est activée. Elle est séparée en deux, parce que `CampaignSnapshot` vit dans `campaign.ts` (comme le demande la fiche) et non dans `types.ts`. `export {}` n'est plus nécessaire : le fichier contient maintenant de vrais exports. **Ce sont les deux seuls types que le reste de l'application peut importer** ; T1.12 s'en servira pour `src/types.ts`.

## 6. Décisions et alternatives

| Décision                                                                                                                                                  | Alternative écartée                                              | Raison                                                                                                                                                                                                                   |
| --------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Sous-types nommés (`FormField`, `LegalLink`, `WheelSegment`, `PrizeChip`, `QuizQuestionTranslation`, `CampaignPrize`, `QuizRules`…)                       | Tableaux d'objets écrits en ligne, comme dans l'esquisse du plan | Même structure exacte ; mais les fonctions, les composants et les tests pourront nommer « un segment » ou « un lien » au lieu de réécrire la forme                                                                       |
| Commentaires en anglais, et seulement là où la règle n'est pas évidente                                                                                   | Traduire tous les commentaires de l'esquisse                     | Règles R0 et C4. Les commentaires restants portent des invariants (téléphone verrouillé, consentement jamais pré-coché, `shareBonus`, pas de bonne réponse…)                                                             |
| `IconName = string` provisoire                                                                                                                            | Créer le registre d'icônes maintenant                            | Prévu en T1.7 par la fiche                                                                                                                                                                                               |
| Types non `readonly` en profondeur                                                                                                                        | Tout marquer `readonly`                                          | Le Studio construira de nouvelles configurations à partir des anciennes ; un `readonly` profond compliquerait tout le code sans protéger davantage (la configuration est déjà traitée comme immuable par le store, T6.1) |
| **Gardes de type dans le test** : sérialisabilité (`IsJson`), absence de règles dans `GameSettings`, `shareBonus` littéral, statut identique à `Campaign` | Le seul aller-retour JSON demandé par la fiche                   | L'aller-retour ne teste qu'**un** exemple. Les gardes de type vérifient **le type lui-même** : ajouter une fonction ou un seuil à la configuration fera échouer `npm run typecheck`, quel que soit l'exemple             |

## 7. Tests

`src/features/player-experience/domain/types.test.ts` :

| Test                                        | Ce qu'il vérifie                                                                                                                                                                                     | Vérifié par |
| ------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------- |
| Aller-retour JSON d'`ExperienceConfig`      | Un exemple complet, **avec tous les blocs facultatifs remplis** (roue, grattage, boîtes, traductions du quiz, Hit It), ressort identique de `JSON.stringify` puis `JSON.parse` : critère de la fiche | Vitest      |
| `ExperienceConfig` ne contient que du JSON  | `IsJson<ExperienceConfig>` vaut `true` : ni fonction, ni `Date`, ni objet à méthodes, à n'importe quelle profondeur                                                                                  | `tsc`       |
| Les règles restent hors de la configuration | `hitIt` n'a que `targetIcon` et `targetImage` ; `quiz` n'a que `translations`                                                                                                                        | `tsc`       |
| `shareBonus` verrouillé                     | Son type est exactement `false`                                                                                                                                                                      | `tsc`       |
| Aller-retour JSON de `CampaignSnapshot`     | Idem, pour l'instantané de campagne                                                                                                                                                                  | Vitest      |
| `CampaignSnapshot` ne contient que du JSON  | `IsJson<CampaignSnapshot>` vaut `true`                                                                                                                                                               | `tsc`       |
| Statuts identiques                          | `CampaignSnapshot["status"]` = `Campaign["status"]` de l'application                                                                                                                                 | `tsc`       |
| `IsJson` lui-même                           | Refuse une fonction, une `Date`, une fonction dans un tableau d'objets ; accepte des textes et des listes                                                                                            | `tsc`       |

**Comment fonctionne `IsJson`** : un type qui parcourt récursivement un autre type. Textes, nombres, booléens, `null` et champs absents donnent `true` ; une fonction donne `false` ; une liste est jugée sur ses éléments ; un objet vaut `true` seulement si **tous** ses champs valent `true`. Les méthodes d'un `Date` sont des fonctions : un `Date` est donc refusé.

**Preuve que les gardes ne sont pas creuses**, par deux modifications temporaires de `types.ts` :

1. ajout de `onSave?: () => void` dans `features` : `tsc` échoue (`types.test.ts(197)`, garde « only holds JSON values ») ;
2. ajout de `winThreshold: number` dans `hitIt` : `tsc` échoue (`types.test.ts(202)`, garde « keeps game rules out »).

Fichier restauré (vérifié avec `cmp`), puis `tsc` passe.

## 9. Écarts, imprévus et points d'attention

- **Gardes de type ajoutées** au-delà de la fiche (§6), ainsi que des sous-types nommés.
- **À décider plus tard : les écrans d'attente et de statut ne sont pas éditables.** `ScreenKey` ne liste que 5 écrans (accueil, inscription, jeu, gain, perte), comme le plan. Les textes de « Préparation de votre partie… », « Vous avez déjà participé », « Campagne terminée » et « Problème de connexion » ne sont donc **pas** personnalisables par la marque : ils viendront des textes par défaut (T1.7), en fr/ar/en. C'est cohérent avec la maquette validée, où le panneau Content ne propose que ces 5 écrans. Si tu veux que la marque puisse les modifier, il suffira d'ajouter une clé `status` à `ScreenKey`, avec une migration.
- **Invariant non exprimable par le type :** la langue par défaut doit faire partie des langues activées (`locales.default ∈ locales.enabled`). Le schéma zod (T1.6) le vérifiera.
- **`IconName` est encore `string`** ; il sera restreint en T1.7.

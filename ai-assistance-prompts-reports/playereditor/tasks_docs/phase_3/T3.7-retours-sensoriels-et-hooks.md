## 1. Objectif

Donner au runtime ses **retours sensoriels** (sons, confettis, vibration) et ses **utilitaires transverses** : mouvement réduit, identifiant de session, copie dans le presse-papiers, temps passé. Les écrans (phase 4) et les jeux (phase 5) en ont besoin : le son de la roue, les confettis du gain, le code à copier, le contexte envoyé avec la participation.

## 5. Le code expliqué

### 5.1 Les sons (`feedback/audio.ts`)

**Six sons synthétisés** avec l'API Web Audio : aucun fichier à télécharger. Ce sont les sons de `player-editor/aktera-audio.ts` (que le prototype partage), aux mêmes fréquences et durées :

| Son         | Rendu                                                               | Usage prévu                   |
| ----------- | ------------------------------------------------------------------- | ----------------------------- |
| `click`     | Glissement bref de 420 à 160 Hz                                     | Boutons (déjà branché au CTA) |
| `tick`      | Triangle de 700 à 300 Hz, 30 ms                                     | Chaque segment de la roue     |
| `countdown` | Bip de 880 Hz, 40 ms                                                | Dernières secondes du chrono  |
| `scratch`   | Bruit filtré (passe-bande 1800 Hz), 40 ms                           | Grattage                      |
| `win`       | Accord majeur montant do-mi-sol-do, la dernière note plus brillante | Gain                          |
| `lose`      | Accord mineur descendant sol-mi♭-do                                 | Perte                         |

Les notes sont décrites comme des **données** (`Tone` : fréquence, glissement, forme d'onde, départ, durée, volume, attaque), jouées par une seule fonction `playTone`, plutôt que six fonctions presque identiques comme dans la source.

**Le premier geste d'abord.** Les navigateurs n'autorisent le son qu'après un geste de l'utilisateur. Ici :

```ts
export function createAudioFeedback(createContext = browserContext): AudioFeedback {
  let context: AudioContext | null = null; // aucun contexte avant le premier geste
  let enabled = true;
  return {
    unlock() { context ??= createContext(); if (context?.state === "suspended") void context.resume().catch(() => {}); },
    setEnabled(value) { enabled = value; },
    play(sound) { if (!enabled || !context) return; try { … } catch { /* silence */ } },
  };
}
```

- **Aucun `AudioContext` n'existe** avant `unlock()`. Un `play()` avant le premier geste ne fait rien.
- `unlockOnFirstGesture(document, audio)` écoute `pointerdown`, `keydown` et `touchend` **en phase de capture**, déverrouille au premier, puis **cesse d'écouter**. La capture compte : le déverrouillage passe avant le gestionnaire du bouton, si bien que le clic qui a débloqué l'audio fait déjà son son.
- **Muet tant que `features.sound` est faux** (`setEnabled`).
- **Jamais d'erreur bloquante** : création refusée, contexte absent (pas de Web Audio), `resume()` rejeté, nœud refusé : tout est rattrapé. Un son est un agrément ; le jeu continue en silence.
- `runtimeAudio` : **une instance par document du runtime** (la page, ou l'iframe de l'aperçu).

**Branché au cadre** : `ExperienceFrame` déverrouille l'audio au premier geste, suit `features.sound`, et **joue « click » avant chaque action du CTA**, comme le `Slot7Cta` du prototype. Pas de son sur un bouton désactivé ou en chargement : ils n'émettent pas d'action.

### 5.2 Les confettis (`feedback/confetti.ts`)

**Le problème** : par défaut, `canvas-confetti` crée son propre canvas plein écran, dans le document qui importe la bibliothèque. Dans le Studio, les confettis couvriraient le Studio, pas l'aperçu.

**La solution** (fiche) :

```ts
const canvas = doc.createElement("canvas"); // doc = le document du runtime
Object.assign(canvas.style, {
  position: "fixed",
  inset: "0",
  width: "100%",
  height: "100%",
  pointerEvents: "none",
  zIndex: "60",
});
doc.body.appendChild(canvas);
launcher = { canvas, fire: confetti.create(canvas, { resize: true }) };
```

- **Un canvas par document**, créé au premier gain, gardé ensuite (`WeakMap<Document, …>`). Le document est celui de l'élément racine du thème (`themeRoot.ownerDocument`) : dans l'aperçu, c'est l'iframe.
- **Dimensionné sur le viewport de ce document** (`fixed` + 100 %), et **redimensionné pendant l'animation** (`resize: true`).
- **Aux couleurs de la marque** : `--xp-primary`, `--xp-primary-light`, `--xp-secondary` et `--xp-accent`, lues sur la racine du thème (seulement les valeurs hexadécimales que la bibliothèque comprend ; sinon, sa palette par défaut). Aucune couleur écrite dans le code (C5).
- **Cinq salves** (reprises de `confettiUtils.ts`) : un éventail serré, puis une pluie plus large, 200 confettis au total.
- **Rien en mouvement réduit** : `celebrate()` renvoie `false` sans créer de canvas.
- Au-dessus de la feuille légale (z-index 60 contre 50), et jamais cliquable (`pointer-events: none`, `aria-hidden`).
- `disposeConfetti(doc)` arrête les salves et retire le canvas.

### 5.3 La vibration (`feedback/haptics.ts`, hors fiche)

`vibrate("tap")` (10 ms) et `vibrate("win")` (30-60-30 ms), si l'appareil le permet (`navigator.vibrate`) ; rien ailleurs (ordinateurs, Safari sur iOS), sans erreur. Prévue par le plan (§8.6) et par D11 ; c'est un retour sensoriel, d'où sa place dans cette tâche.

### 5.4 Les hooks

| Hook                                  | Ce qu'il rend                                                                                                                          |
| ------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| `useReducedMotion(animationsEnabled)` | `true` si le système demande moins de mouvement (`prefers-reduced-motion`, suivi en direct) **ou** si la marque a coupé les animations |
| `useSessionId()`                      | L'identifiant de la visite, avec la **clé et le format de la production** (`octoreach_session_id`, `sess_<horodatage>_<aléa>`)         |
| `useCopyToClipboard(ms)`              | `{ copied, copy(text) }` : `copied` reste vrai `ms` millisecondes (2 s par défaut)                                                     |
| `useDwellTime()`                      | Une fonction qui lit les secondes passées depuis l'apparition, **sans provoquer de rendu**                                             |

- **`useSessionId`** : même clé que `PlayerFlowPage.tsx`, pour qu'une visite garde un seul identifiant de l'impression au tirage. Si le stockage est bloqué (navigation privée, iframe restreinte), un identifiant en mémoire, stable pendant toute la page (C7). Lu une seule fois par montage.
- **`useCopyToClipboard`** : l'API Clipboard d'abord ; si elle est absente ou refusée, une zone de texte cachée et `execCommand("copy")`, retirée aussitôt. `copy()` dit si cela a marché et ne lance jamais d'erreur : l'écran de gain garde le code lisible dans tous les cas. Une seconde copie relance la minuterie ; elle est effacée au démontage.
- **`useDwellTime`** : l'heure d'arrivée est lue une fois, au montage ; le résultat n'est jamais négatif (horloge reculée).

### 5.5 La page de contrôle `feedback-debug`

`/xp-frame?fixture=feedback-debug` : un bouton par son, « Confetti », « Vibrate », « Copy session id », et l'état de chaque utilitaire (son verrouillé ou non, mouvement réduit, identifiant de session, dernière action). Elle sert à essayer chaque retour dans un vrai navigateur et sur un vrai téléphone (le son et la vibration ne se testent pas autrement).

## 6. Décisions et alternatives

| Décision                                           | Alternative écartée                          | Raison                                                                                               |
| -------------------------------------------------- | -------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| Aucun `AudioContext` avant le premier geste        | Contexte créé au chargement, puis `resume()` | Chrome signale un contexte créé sans geste ; rien n'existe tant que le joueur n'a pas touché l'écran |
| Déverrouillage en phase de capture sur le document | Déverrouillage dans chaque bouton            | Un seul point, et le geste qui déverrouille fait déjà son son                                        |
| Sons décrits en données (`Tone`)                   | Six fonctions recopiées de la source         | Mêmes sons, un tiers du code, et un test qui vérifie les notes                                       |
| Un canvas de confettis par document, à nous        | Canvas par défaut de `canvas-confetti`       | Fiche : confinés au document du runtime (sinon ils couvrent le Studio)                               |
| Couleurs lues dans les variables du thème          | Palette écrite (celle de `confettiUtils.ts`) | Confettis aux couleurs de la marque (§6.3) ; aucune couleur écrite (C5)                              |
| `useDwellTime` rend une fonction                   | Un état mis à jour chaque seconde            | Le temps ne sert qu'au moment de l'envoi : aucun rendu inutile                                       |
| `vibrate` ajouté (`haptics.ts`)                    | Laissé aux jeux                              | Prévu par le plan et D11 ; un seul endroit, testé                                                    |
| Page de contrôle `feedback-debug`                  | Rien avant les écrans                        | Le son et la vibration ne se vérifient que sur un vrai appareil                                      |

## 9. Écarts, imprévus et points d'attention

- **Ajouts hors fiche** (à valider, R5) : `haptics.ts` (vibration, §5.3) ; la page de contrôle `feedback-debug` ; le **son de clic branché au CTA** (parité avec le prototype, D1).
- **ESLint** refuse les noms de types DOM sans valeur globale (`OscillatorType`, `VibratePattern`, `AudioContextState`), comme en T3.2 : ils sont écrits à partir des types des objets (`OscillatorNode["type"]`, `AudioContext["state"]`).
- **Deux simplifications** après la mesure de couverture : `useDwellTime` lit l'heure d'arrivée une seule fois au montage (`useState`), et la page de contrôle lit les couleurs des confettis sur le bouton lui-même (les variables CSS s'héritent).
- **Deux tests renforcés** avant les mutations : l'arrêt de l'écoute après le premier geste, et la clé de session comparée littéralement à celle de la production (le test comparait la constante à elle-même).
- **Pas de réglage « couper le son » pour le joueur** : `features.sound` est le réglage de la marque ; un bouton muet pour le joueur n'est ni dans la fiche ni dans le plan.

## 5. Le code expliqué

### 5.1 Les images : pourquoi un « codec » injectable

Décoder et réencoder une image demande le navigateur (`createImageBitmap`, `<canvas>`). Or l'environnement des tests (jsdom) n'a ni l'un ni l'autre. Le travail est donc coupé en deux :

| Partie                      | Rôle                                                                       | Testée avec                                                                                    |
| --------------------------- | -------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------- |
| `ImageCodec`                | Décoder un fichier ; dessiner une image à une taille donnée et l'encoder   | Le vrai codec (`browserImageCodec`) avec des **doublures** de `createImageBitmap` et du canvas |
| `createDataUrlAssetStorage` | Toutes les décisions : type accepté, taille cible, format, limite, erreurs | Un **faux codec** qui enregistre ce qu'on lui demande                                          |

`browserImageCodec` est le codec par défaut. Deux détails de qualité :

- **Orientation** : `imageOrientation: "from-image"`, pour qu'une photo de téléphone ne s'affiche pas couchée.
- **JPEG et transparence** : le JPEG n'a pas de transparence ; sans précaution, les zones transparentes deviendraient **noires**. Le canvas est donc peint en blanc avant de dessiner.

### 5.2 Les décisions de `upload(fichier, usage)`

| Étape    | Règle                                                                                                                                                                       | Erreur                                                                        |
| -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------- |
| Type     | Le fichier doit être déclaré `image/…`                                                                                                                                      | `NOT_AN_IMAGE` : « This file is not an image. Use a PNG, JPEG or WebP file. » |
| Décodage | Le navigateur doit savoir le lire                                                                                                                                           | `UNREADABLE` : « This image could not be read… »                              |
| Taille   | Côté le plus long ramené à : fond **1920 px**, couverture à gratter **1280 px**, logo **512 px** ; une petite image n'est **jamais agrandie**                               | —                                                                             |
| Format   | **WebP** à 0,82. Si le navigateur ne sait pas encoder le WebP (il renvoie alors du PNG), repli sur **JPEG** pour les photos et **PNG** pour les logos, souvent transparents | —                                                                             |
| Poids    | 400 Ko au plus **après** compression (la même limite que la validation, T1.11)                                                                                              | `TOO_LARGE` : « This image is still over 400 KB after compression… »          |
| Résultat | `data:image/…` seulement (le schéma, T1.6, refuse tout autre type)                                                                                                          | `UNREADABLE` sinon                                                            |

L'image décodée est **toujours libérée** (`close()`), même en cas d'erreur, pour ne pas garder de mémoire inutilement.

`resolveUrl(ref)` : renvoie l'adresse à afficher. `data:` et `https:` telles quelles ; un objet Supabase Storage passe par une fonction `resolveStorage`, qui renvoie `null` tant que l'adaptateur Supabase n'existe pas (« préparation future »).

## 6. Décisions et alternatives

| Décision                                           | Alternative écartée                                    | Raison                                                                                          |
| -------------------------------------------------- | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------- |
| Codec injectable                                   | Tester seulement en navigateur réel                    | jsdom n'a pas de canvas ; la logique de décision est testée à 100 % sans navigateur             |
| Repli **PNG** pour les logos                       | JPEG partout (fiche)                                   | Un logo transparent aurait un fond blanc ou noir en JPEG ; un logo de 512 px reste léger en PNG |
| Fond blanc avant un JPEG                           | Laisser le noir par défaut du canvas                   | Une image transparente convertie en JPEG ne doit pas devenir noire                              |
| Orientation EXIF respectée                         | Valeur par défaut du navigateur                        | Les photos prises au téléphone s'afficheraient couchées dans certains navigateurs               |
| Une seule compression (0,82)                       | Réessayer avec une qualité plus basse avant de refuser | Conforme à la fiche ; amélioration possible si des photos réelles dépassent souvent 400 Ko      |
| Fabriques (`create…()`) pour les trois adaptateurs | Objets exportés tels quels                             | Même forme que les autres adaptateurs ; options injectables                                     |

## 9. Écarts, imprévus et points d'attention

- **Correction d'une erreur de ma part (T2.3).** Pour vérifier la couverture, je cherchais chaque fichier par son nom dans le rapport. Or le rapport **tronque les noms longs** (« ...EntryStore.ts ») : une branche non couverte de `demoEntryStore.ts` m'avait échappé, et la documentation de T2.3 annonçait à tort 100 %. Test complété ici, documentation de T2.3 corrigée. Je filtre maintenant le rapport sur toutes les lignes sous 100 %, quel que soit le nom : c'est ainsi que les deux trous ont été trouvés.
- **ESLint** : `CanvasImageSource` est un type TypeScript sans équivalent à l'exécution, et la règle `no-undef` le refusait. Remplacé par `DrawableImage`, dérivé de `CanvasRenderingContext2D`.
- **Le vrai rendu d'image** (qualité visuelle, poids réels) ne peut être vérifié qu'en navigateur : ce sera fait avec le Studio (phase 6). Si des photos ordinaires dépassent souvent 400 Ko, une deuxième compression à qualité plus basse pourra être ajoutée.
- **Pas de latence simulée** pour l'upload : il se fait dans le navigateur, sans réseau.

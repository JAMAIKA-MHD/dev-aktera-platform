## 1. Objectif

Décrire, sous forme d'**interfaces TypeScript seulement**, tout ce dont l'expérience a besoin du monde extérieur :

- stocker la configuration ;
- faire participer un joueur ;
- stocker une image ;
- mesurer l'audience ;
- vérifier qu'un joueur est humain.

C'est le principe « ports et adaptateurs » : le runtime et le Studio parlent à ces interfaces, jamais à `localStorage` ou à Supabase directement. Aujourd'hui, les adaptateurs sont locaux (T2.2 à T2.5) ; après le MVP, des adaptateurs Supabase implémenteront **les mêmes interfaces**, sans rien changer au reste.

## 5. Le code expliqué

### 5.1 Un principe : les échecs attendus sont des valeurs

Un conflit d'enregistrement, un stockage plein ou un fichier refusé ne sont pas des bugs : ce sont des situations **normales** que l'écran doit expliquer. Ils sont donc **renvoyés** sous la forme `{ ok: false, error }`, comme `DrawResult` (T1.5), et jamais lancés comme exceptions. TypeScript oblige alors l'appelant à traiter les deux cas : impossible d'oublier d'afficher « stockage plein ».

### 5.2 Les 5 ports

| Port                   | Méthodes                                                                           | Rôle                                                                                    |
| ---------------------- | ---------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------- |
| `ExperienceRepository` | `load(scope)`, `save(config, { expectedUpdatedAt })`, `remove(scope)`              | Lire et écrire la configuration d'une campagne                                          |
| `ParticipationGateway` | `mode`, `checkAvailability(campaignId)`, `draw(request)`, `confirmCoupon(entryId)` | **Seule autorité** sur les résultats : serveur en production, simulation dans le Studio |
| `AssetStorage`         | `upload(file, purpose)`, `resolveUrl(ref)`                                         | Stocker une image (logo, fond, couverture à gratter) et la réafficher                   |
| `AnalyticsTracker`     | `track(event)`                                                                     | Mesurer l'audience ; « tire et oublie » : ne bloque ni ne casse jamais le parcours      |
| `HumanVerification`    | `getToken()`                                                                       | Captcha ; au MVP, renvoie toujours `null`                                               |

`ExperienceServices` les regroupe tous : c'est l'objet que `ServicesProvider` (T2.6) injectera dans l'arbre React.

### 5.3 Détails par port

**Configuration (`ExperienceRepository`).**

- `load` renvoie `null` si rien n'est enregistré. Sinon, un `ParseResult` (T1.6) : la configuration, **toujours utilisable** (migrée, validée, réparée), avec la liste des problèmes trouvés. Le Studio pourra ainsi dire « votre configuration a été réparée ».
- `scope.fallbackGameType` indique le jeu à utiliser si les données enregistrées sont illisibles, pour reconstruire une configuration du **bon** jeu.
- `save` accepte `expectedUpdatedAt` : si la configuration enregistrée a changé depuis son chargement (autre onglet), l'enregistrement est refusé (`CONFLICT`) au lieu d'écraser le travail de l'autre onglet.
- Erreurs : `CONFLICT`, `STORAGE_FULL` (quota dépassé, souvent à cause d'images), `STORAGE_UNAVAILABLE` (stockage bloqué, par exemple en navigation privée).

**Participation (`ParticipationGateway`).** Trois modes :

| Mode       | Adaptateur                                  | Usage                  |
| ---------- | ------------------------------------------- | ---------------------- |
| `live`     | Edge Function `select-prize` (après le MVP) | Production             |
| `demo`     | Tirage simulé honnête (T2.3, T2.4)          | Studio, démonstrations |
| `scripted` | Résultat choisi dans le Studio (T2.4)       | Vérifier chaque écran  |

Le mode est lisible (`readonly mode`) : la page publique refusera tout autre mode que `live` (plan §7.4).

**Images (`AssetStorage`).** `upload` renvoie `{ ok: true, asset }` ou une erreur `NOT_AN_IMAGE`, `TOO_LARGE` (encore trop lourde après compression) ou `UNREADABLE`.

**Analytics.** `ExperienceEvent` porte le nom de l'événement (13 noms, plan §7.5), l'heure, la campagne, la session, l'écran et la langue. `data` n'accepte que des valeurs simples, et le commentaire rappelle **qu'aucune donnée personnelle** (téléphone, nom, email) n'y a sa place.

## 6. Décisions et alternatives

| Décision                                                        | Alternative écartée                                 | Raison                                                                                                                                |
| --------------------------------------------------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| `save` renvoie `SaveResult` (`ok` / `error`)                    | `Promise<ExperienceConfig>` qui rejette (plan §7.1) | Échecs attendus traités comme des valeurs, comme `DrawResult` ; la fiche T2.2 demande d'ailleurs de « renvoyer une erreur explicite » |
| `load` renvoie `ParseResult \| null`                            | `ExperienceConfig \| null` (plan)                   | Le critère de T2.2 exige les `issues` d'une configuration réparée                                                                     |
| `upload` renvoie `UploadResult`                                 | `Promise<AssetRef>` qui rejette (plan)              | Même principe ; T2.5 doit signaler « fichier texte → erreur »                                                                         |
| `confirmCoupon` et `checkAvailability` gardent la forme du plan | —                                                   | Déjà des résultats sous forme de valeurs                                                                                              |
| `scope.fallbackGameType` facultatif                             | Portée limitée à `campaignId`                       | Reconstruire le bon jeu quand les données sont illisibles                                                                             |
| `ExperienceEvent` en `interface`                                | `type` (fiche)                                      | Équivalent ; cohérent avec les autres déclarations                                                                                    |

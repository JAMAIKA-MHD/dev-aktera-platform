## 5. Le code expliqué

### Les dossiers et les `.gitkeep`

Git ne suit pas les dossiers vides. Un fichier vide `.gitkeep` dans chaque dossier « feuille » les rend visibles dès maintenant, pour que la structure soit relisible avant d'être remplie. Chaque `.gitkeep` pourra être supprimé quand le premier vrai fichier arrivera dans son dossier.

L'arborescence est celle du plan §4.2 **dans sa version révisée**, qui ajoute `runtime/layout` (mise en page adaptative), `runtime/host` (iframe `/xp-frame`) et `studio/preview` (aperçu façon DevTools). Les sous-dossiers plus fins (par exemple `runtime/games/wheel/` ou `studio/panels/game/`) seront créés par les tâches qui les remplissent.

### `eslint.config.js`, bloc 4 : les frontières d'import

**Règle 1 : hors du module, seul `index.ts` peut être importé.**

```js
{
  files: ["**/*.{js,mjs,cjs,jsx,ts,tsx}"],
  ignores: ["src/features/player-experience/**"],
  rules: {
    "no-restricted-imports": ["error", { patterns: [{
      group: ["**/player-experience/*", "!**/player-experience/index"],
      message: "Import the Player Experience module through its public entry point (src/features/player-experience/index.ts) only.",
    }] }],
  },
},
```

- **`files` + `ignores`** : la règle s'applique à tous les fichiers du projet, **sauf** ceux du module. À l'intérieur, les fichiers s'importent librement entre eux (dans le respect des couches).
- **`group`** suit la syntaxe de `.gitignore`, appliquée au texte de l'import :
  - `**/player-experience/*` interdit tout ce qui se trouve **sous** le module, par exemple `./features/player-experience/domain/types` ou `@/src/features/player-experience/runtime/...`, à n'importe quelle profondeur ;
  - `!**/player-experience/index` rend l'autorisation explicite pour `…/player-experience/index`.
- **L'import du dossier seul**, `./features/player-experience`, n'est pas concerné par le motif (rien après le dernier `/`). C'est la forme normale, et elle est autorisée.
- **`**/` au début** couvre les trois façons d'écrire un chemin : relative (`./features/...`, `../player-experience/...`), avec l'alias `@/src/...`, ou absolue.

**Règle 2 : dans `runtime/`, pas d'adaptateur local.**

```js
{
  files: ["src/features/player-experience/runtime/**/*.{ts,tsx}"],
  rules: {
    "no-restricted-imports": ["error", { patterns: [{
      group: ["**/services/local", "**/services/local/*"],
      message: "The runtime must not import local adapters: receive services through ServicesProvider (useExperienceServices).",
    }] }],
  },
},
```

- **Pourquoi c'est vital :** la passerelle de démonstration, qui tire les lots dans le navigateur, vit dans `services/local/`. Si le runtime pouvait l'importer directement, il pourrait un jour tirer un lot côté client sur la page publique, ce qui violerait la règle N1. Le runtime reçoit donc ses services **par injection** ; ESLint empêche le raccourci.
- **Deux motifs**, car l'import peut viser le dossier (`../services/local`) ou un fichier (`../services/local/demoParticipationGateway`).
- **`services/ports` reste autorisé :** c'est l'interface, pas l'implémentation.

**Pas de conflit entre les deux blocs :** le premier exclut les fichiers du module, le second ne concerne que ceux du runtime. Aucun fichier ne reçoit les deux (sinon, en configuration « flat », le second remplacerait le premier).

## 6. Décisions et alternatives

| Décision                                        | Alternative écartée                                                                           | Raison                                                                                                                                                                                               |
| ----------------------------------------------- | --------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Motif `**/player-experience/*`                  | `**/features/player-experience/*`                                                             | Couvre aussi les imports relatifs écrits depuis un dossier voisin (`../player-experience/domain`)                                                                                                    |
| Seulement les 2 règles de la fiche              | Bloquer aussi, dès maintenant, `domain/` → React, `services`, `runtime`, `studio` (plan §4.3) | Règle R5 : la fiche en prévoit 2. **Proposition** : ajouter cette troisième règle, au plus tard en T1.1, pour protéger le domaine dès son premier fichier. Coût : environ 10 lignes de configuration |
| Exports prévus en commentaire dans `index.ts`   | Un `index.ts` vide                                                                            | La liste documente l'API publique à venir, avec la tâche responsable de chaque export                                                                                                                |
| `.gitkeep` seulement dans les dossiers feuilles | Un `.gitkeep` dans chaque dossier                                                             | Git suit un dossier dès qu'un de ses sous-dossiers contient un fichier                                                                                                                               |

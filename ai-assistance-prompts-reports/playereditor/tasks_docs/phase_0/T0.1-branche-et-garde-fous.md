## 1. Objectif

Isoler le travail de refactorisation et empêcher le prototype AI Studio (`aktera---gamified-marketing-experience/`) de perturber `lint`, `typecheck` et `build`.

Le prototype est une **source de lecture** : on y prend des idées et du visuel, mais il ne fait pas partie de l'application. Tant que les outils du projet l'analysaient, ses défauts devenaient ceux du projet : **aujourd'hui, `npm run lint` échouait uniquement à cause de lui**.

## 2. Où elle se situe

- **Avant :**
  - `tsconfig.json` n'a pas de clé `include`, donc TypeScript analyse tout le dossier, prototype compris ;
  - `eslint .` analyse aussi tout le dossier.
- **Après :** les deux outils ignorent le prototype. Toutes les tâches suivantes s'appuient sur des commandes `lint` et `typecheck` qui ne reflètent que le code du projet.
- **Plus tard (T7.3) :** le prototype sera déplacé hors du dépôt ou archivé. Ces exclusions deviendront alors inutiles, mais resteront sans effet négatif.

## 5. Le code expliqué

### `tsconfig.json`

```json
"exclude": [
  "node_modules",
  "supabase/functions",
  "old-ui-ode",
  "old-ui-code",
  "aktera---gamified-marketing-experience"
]
```

- **Pourquoi `exclude` et pas `include` ?** Le projet n'a pas de liste `include`. TypeScript prend donc par défaut **tous** les fichiers `.ts`/`.tsx` sous la racine, sauf ceux de `exclude`. Ajouter une entrée à `exclude` est le changement le plus petit, et suit la convention déjà en place (`supabase/functions`, `old-ui-code`).
- **Effet mesuré :** TypeScript analysait 1 027 fichiers, dont 35 du prototype. Il en analyse maintenant 992, dont 0 du prototype (mesuré avec `tsc --noEmit --listFilesOnly`).
- **Limite à connaître :** `exclude` n'empêche pas TypeScript de suivre un `import` explicite vers le prototype. Aucun fichier du projet ne l'importe, et la règle R7 interdit de le faire.

### `eslint.config.js`

```js
{
  ignores: [
    // …
    ".supabase/**",
    "**/.supabase/**",
    // AI Studio design prototype: read-only reference for the Player Experience refactor
    "aktera---gamified-marketing-experience/**",
  ],
},
```

- **Pourquoi dans ce bloc ?** Dans la configuration « flat » d'ESLint, un objet qui ne contient **que** `ignores` s'applique globalement : les fichiers listés ne sont jamais analysés, par aucune règle. C'est le bloc « 1. Ignore build artifacts » déjà utilisé pour `dist/`, `supabase/`, etc.
- **Le commentaire** (en anglais, règle R0) explique pourquoi ce dossier est ignoré, ce qui n'est pas évident à la lecture.
